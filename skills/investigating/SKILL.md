# 调查与笔记

开始时声明："正在使用 rivo:investigating，查清这个问题并更新调查笔记。"

**核心原则：** 从实际入口追到结果，用能区分真假的证据回答问题，把认识按主题维护在同一份 note.md 里。

本技能是方法技能：结果交回当前工作，不另建进度。

## 流程

### 1. 确定问题

先写清：
- **问题**：要回答什么，答案影响哪个判断
- **范围**：允许调查的项目和操作

再读已有认识：
- note.md、项目知识库和相关资料，核实已有结论是否适用
- 读了知识库，把它的版本（提交号或修改时间）记进 note.md 的调查范围，收尾合并时要用
- 验证新候选方案时，写明假设、输入和预期结果

### 2. 沿行为查证

- **从入口追到结果**：检查调用方、数据变化、配置、存储和失败路径
- **看实际接入**：找到类型、接口或文件，不等于能力已经接入
- **复用前核对**：输入输出、实际行为、接入条件和业务差异
- **用能区分真假的场景验证**
- **标明证据类型**：代码推断、实验观察、真实运行分开写；静态分析不能冒充联调
- **证据冲突时回查来源和版本**，不挑最方便推进的那条

需要独立探索时，按 [调查委派提示词](references/investigation-prompt.md) 派子代理，给它已有认识、缺口和范围。子代理只返回证据，由你核对后整合进 note.md，免得多人各自追加矛盾结论。

### 3. 结束调查

- 能回答问题并说明限制，就结束
- 仍有缺口：说明影响和下一项有效检查，不扩大成全仓扫描
- 实验代码不自动成为正式实现

### 4. 更新 note.md

- 位置：当前需求的 `.rivo/issues/<slug>/note.md`；单独调查用 `.rivo/issues/<topic>/note.md`；用户或项目指定的优先
- 有新发现时先读当前主题，在原处重写受影响的内容，按 writing-clearly 修订
- 仍适用于其他版本或范围的结论保留，写明适用范围
- 重新核对结论与原始证据，检查相关主题有无冲突

### 5. 交回结果

- 直接结论和关键依据
- 尚未查明的部分
- 哪些原认识被改变，哪些已有材料（ADR、方案、实现）可能需要修订

新证据与 ADR、plan.md 或已完成的实现冲突时，带着原结论、新证据和影响交回当前工作，由它决定怎样处理；单独调查时交给用户。

## note.md 的组织

像专题 Wiki 一样按机制或问题分主题，例如"字段转换""附件存储""配置生效"。写法按 writing-clearly。

```markdown
# <主题或需求>：调查笔记

## 调查范围
本次关心的系统、问题和适用版本；读取的知识库版本。

## <机制或问题>
当前认识：负责什么，实际怎样工作。
关键链路与契约：入口、调用、数据与配置，必要时配图和字段表。
适用边界：已验证到哪里，哪些是推断或尚未确认。
依据：代码、配置、实验或运行结果及其适用版本。
待核实：尚缺什么证据，它会影响哪个判断。
```

note.md 只保存项目机制和验证结论：
- 目标方案写进 plan.md，实施安排写进 task.md，重要取舍写进 adr/
- 不按日期记流水，不为每次调查另建报告

需求的笔记在验收后由 knowledge-management 整理进知识库；单独调查的笔记，由用户单独调用 knowledge-management 整理。

## 常见错误

| 你在想 | 应当怎么做 |
| --- | --- |
| "代码里有这个接口，功能已经有了" | 追到实际调用和运行结果。 |
| "笔记更新了，方案应该还成立" | 说明哪些已有材料可能要修订，交回当前工作。 |
| "顺便把整个仓库扫一遍" | 只查回答当前问题需要的范围。 |
| "查到了，顺手把方案也改了" | 调查只交回证据，决定由当前工作或用户做。 |
