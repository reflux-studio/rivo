# 查证技术事实

围绕具体问题调查，说明答案影响哪个判断、相关系统和允许的操作。先读已有证据及适用版本，避免重复调查。需要试验时区分实验与正式实现，实验授权不自动扩大到产品变更。

## 从入口追到结果

核对调用方、实际输入、数据与状态变化、存储和输出。找到类型、字段或文档声明不能证明链路已经接入。复用能力前检查输入输出、边界和真实接入条件；验证候选做法时给出假设与能区分真假的场景。

将代码推断、实验结果和真实运行分开报告。证据冲突时回查版本、范围和来源，不选择最方便继续推进的那条。检查足以回答问题就结束；无法继续时说清缺口和下一项有效检查，不扩大成无边界的全仓扫描。

可独立拆开的调查按 [调查委派提示词](references/investigation-prompt.md) 派子代理，明确问题、已有结论、范围和操作限制。主代理核对结果后整合，不因来自另一代理就视为证实。

## 保存能复用的结论

在当前需求的 note.md 按机制或问题更新：结论、成立条件、关键证据和未确定部分。证据标明版本或环境；知识库的初始读取版本也保存在这里。已有结论失效时在原处修正，仍适用于其他范围的保留其边界，不按调查日期堆流水。

note 还保留原始需求依据、批准的范围变化和讨论期间暂存的决定，分别标清来源，不混成技术事实。决定写入 plan 后，移除重复的临时设计叙述，保留可追溯的来源和未解决事项。重要取舍用 ADR，实施进度用 task，不在调查笔记里重新设计交付流程。

## 返回当前工作

给出直接答案、证据类型和限制。新事实与已有决定、方案或实现冲突时，说明原约定和实际后果；事实本身由 AI 查证，是否改变重要约定按已有授权或交用户决定。

调查完成后继续原任务。单独调查只交事实与影响，不擅自改方案、实现或知识库；用户要求整理知识时进入 knowledge-management。
