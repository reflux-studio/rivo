# Architecture Decisions

开始时声明：“正在使用 rivo:architecture-decisions，比较或记录当前重要选择。”同一阶段已声明时不重复。写作时使用可用的 `writing-clearly-and-concisely` 技能。

调查、比较并记录一项重要选择。需求、设计和实施阶段均可调用。已有结论直接记录，尚未决定则先调查和比较。

## 何时值得单独处理

问题涉及重要的职责边界、共享模型、接口承诺、数据语义、依赖或难以逆转的安排，且需要集中推演或长期解释时使用。常规选择可以留在 Spec 或 plan，不为每个函数和分支创建 ADR。

模型说明概念、规则和结构，ADR 解释选择的理由与后果。术语和已知业务事实写入 Spec 或 plan。

## 形成决定

1. 查明当前问题、适用范围、已有决定和实际约束，区分事实、假设与偏好。
2. 比较有实质差异的可行选项，包括适用时沿用现状；不制造陪衬方案。核实关键假设，说明各自的行为、成本、依赖与迁移后果。
3. 涉及模型时，用已有场景和能区分候选的反例检验，说明共同规则与必须保留的差异。额外抽象的理解成本也属于代价。
4. 提出推荐及其依据。重要取舍需要用户判断且没有既有决定时，展示具体后果并等待回应；已有结论直接沿用。
5. 保存决定或提议，核对相关 Spec、plan 和当前知识，说明哪些内容需要更新。方案被接受不代表能力已经实现。

需要图示才能判断时使用可用的绘图能力，沿用当前任务的图源与确认版本；结构对比可参考 [架构图协作参考](../requirements-definition/references/architecture-diagrams.md)。短小选择可用场景表和文字说明。

## Output Location

默认写入本次目标项目根目录的 `.rivo/issues/<slug>/ADR.md`，同一需求沿用已有 slug；独立请求按本次决定主题命名 slug。用户指定或项目配置声明的路径优先；已有记录原位更新。输入资料的位置不决定输出位置；跨仓库沿用当前任务选定的主交付根目录。

在同一文件中按稳定编号追加独立条目，已有按编号拆文件的惯例直接沿用。各条目有自己的状态；已接受决定需要替代时保留原理由和替代关系，不将旧记录改写成从未发生。

## ADR Structure

采用 MADR 的背景、选项、决定和后果结构，记录状态与来源。下方模板可直接使用。

```markdown
# <稳定编号>：<选择主题>
状态：提议／接受／已替代
日期与确认或委托依据：
相关需求、设计与证据：

## 背景与问题
需要决定什么，适用范围、事实与约束是什么。

## 考虑的选项
真实可行的选择及其差异，必要的验证或场景检验。

## 决定与理由
采用什么及其依据；待定时明确写出推荐和未决问题。

## 后果与重新考虑条件
收益、代价、适用边界；哪些证据或变化会促使重看。
替代旧决定时注明双方编号与新依据。
```

## 完成与返回

核对事实来源、候选差异、状态依据和后果。没有确认或委托的建议保持提议，不能用文档状态替代真实决定。返回主要结论、记录位置、未决项及受影响材料；独立请求到此完成，交付中继续当前问题，不自动重跑需求或设计阶段。
