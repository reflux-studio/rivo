# 独立代码审阅

“代码写得好不好”和“需求做对没有”交给两名独立审阅者并行检查，各看各的材料，各出各的结论。分开审，是为了不让整洁的代码盖过漏做的需求，也不让跑通的功能盖过重复实现、放宽的断言或只跑 mock 的测试。

## 流程

### 1. 送审前先跑自动检查

送审前先跑通编译、类型检查、Lint、单元测试和轻量集成测试。低级错误不该占用审阅者的上下文；测试代码和实测输出也要一并交给审阅者核对。

### 2. 并行派两名审阅者

加载 `dispatching-subagents`，按 [审阅者提示词](references/reviewer.md) 并行派两名没有参与本次编码的审阅者。两人用同一种模式：单项改动或整体。

- **审阅者 A（代码质量与规范）**：只给真实代码差异（`git diff`，含未提交与未跟踪文件）、仓库规范、参照样板和组件库要求
- **审阅者 B（需求与方案符合度）**：给真实代码差异、需求与设计依据（含引用的测试用例编号），以及实测命令和原始输出，不只给执行者的口头摘要

两人只读不写，各自返回报告。需要归档时由调用方汇总写入，避免两人同时写一个文件。宿主没有子代理工具时如实说明，不把自查算作独立审阅。

### 3. 核实与处理意见

按 [接收审阅意见](references/receiving-review.md) 对照真实需求、设计和代码逐条核实两份报告。属实的 P0 必须修，修完重跑受影响的检查，交回提出它的审阅者复核，直到两个方向都没有 P0。未修的 P1、P2 和拒绝理由记入交付或任务记录。
