### 验收标准（AC）

以 Given / When / Then 描述端到端、可观察的行为，统一编号为 AC-001、AC-002……这套编号是下游 plan / build / verify 逐条追溯的依据，不可省略。覆盖关键路径 + 主要错误路径，不穷举所有组合。

- **AC-001**：**Given** [前置状态]，**When** [用户动作]，**Then** [预期结果]
- **AC-002**：**Given** [错误前置]，**When** [动作]，**Then** [错误处理]

### 边界情况

- 当 [边界条件] 时会怎样？

## 4. 功能需求（EARS）

每条需求必须**可测试**，且对应**单一可验证**的系统行为。统一用 EARS 句式书写：

| 句式     | 触发词  | 中文模板                                       | 适用场景              |
| -------- | ------- | ---------------------------------------------- | --------------------- |
| 普遍     | —       | 系统应 \<行为\>                                | 始终成立的约束        |
| 事件驱动 | When    | 当 \<事件\> 时，系统应 \<响应\>                | 由某动作 / 事件触发   |
| 状态驱动 | While   | 在 \<状态\> 期间，系统应 \<行为\>              | 在持续状态下成立      |
| 可选特性 | Where   | 若系统包含 \<特性\>，系统应 \<行为\>           | 与配置 / 可选模块相关 |
| 异常行为 | If…Then | 如果 \<异常条件\>，则系统应 \<响应\>           | 错误处理与防护        |
| 复合     | 组合    | 当 \<事件\> 时，如果 \<条件\>，则系统应 \<响应\> | 上述句式的叠加        |

**需求列表：**

- **FR-001**（普遍）：系统应仅允许具备导出权限的角色发起订单导出。
- **FR-002**（事件驱动）：当用户在订单列表点击导出时，系统应创建导出任务并返回任务标识。
- **FR-003**（状态驱动）：在导出任务处理期间，系统应向用户展示该任务的实时状态。
- **FR-004**（异常行为）：如果导出数据量超过 10000 条，则系统应转为异步生成，并在完成后通知用户下载。
- **FR-005**（可选特性）：若系统启用频率限制，系统应在单用户每小时导出超过 5 次时拒绝并提示。

> **标注未决项的写法**——在需求内嵌占位，澄清前不要替用户臆测：
> FR-00X：当导出完成时，系统应通过 [NEEDS CLARIFICATION: 通知方式未定 — 站内信 / 邮件 / 两者都要？] 通知用户。

## 5. 非功能需求

同样可度量、可测试，避免「快」「稳定」「友好」这类无法验证的词。

- **NFR-001**（性能）：当并发导出请求达到 100 时，系统应保证创建任务接口 p95 响应时间低于 200ms。
- **NFR-002**（可用性）：系统应保证订单列表与导出接口 99.9% 的月度可用性。
- **NFR-003**（安全）：系统应仅向发起人开放其导出文件的下载链接。
