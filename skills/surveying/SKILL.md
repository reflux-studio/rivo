# 勘测

摸清项目的一个侧面，落成一份长期契约，给后续所有工作当依据。方法只有一条：**从真实代码与配置归纳，不凭印象、不套通用模板**——契约里的每一条，都应该在代码里找得到出处。

## 勘测哪面、读什么、产出什么

| 侧面 | 先读什么 | 契约（模板） | 特别注意 |
| --- | --- | --- | --- |
| 项目身份 | README、依赖声明、CLAUDE.md 之类给 AI 的协作说明 | [PROJECT.md](../../templates/PROJECT.md) | README 可能过期，对着依赖声明和代码核一遍 |
| 系统架构 | 目录结构、关键源码、依赖声明 | [ARCHITECTURE.md](../../templates/ARCHITECTURE.md) | 只画代码里真有的依赖和分层，规整的理想图会误导下游 |
| 设计系统（前端才有） | 组件代码、样式 / 主题配置、token 定义 | [DESIGN.md](../../templates/DESIGN.md) | 只记真实存在的 token 和组件，拿通用值充数下游会找不到 |
| 代码规约 | 一批有代表性的源码、linter / formatter 配置、提交历史 | [CONVENTIONS.md](../../templates/CONVENTIONS.md) | 惯用法大多没进 linter 配置，得从代码读；只一两处、未成约定的别写成铁律 |
| 验证基建 | README、CI 配置、测试目录与脚本 | [TESTING.md](../../templates/TESTING.md) | 每条命令亲手跑通再记，没跑通的标待确认，不写成「应该能跑」 |

摸什么以模板的小节为准，按需取用，不适用的整段省略；能画 ASCII 图就画。产出写到项目的契约目录（rivo 里是 `.rivo/`）。

## 核心原则

- **宁缺毋滥**：拿不准的留空请用户补，推断标明是推断、请用户确认，不编造。
- **产物即承诺**：契约是后续所有阶段的共同依据，对准确性负责。

## 危险信号

- 「这类项目一般都这样，照写」：要的是这个项目实际怎么样，不是同类一般怎么样。
- 「文档写了，直接抄」：README 和注释常过期，对着代码与配置核实过再记。
