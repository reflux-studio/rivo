# 处理审阅结果

先对照用户需求、当前设计和实际证据核实意见。审阅者可能缺上下文，主代理也可能误判，不能只因某方给了级别就照办。

| 核实结果 | 处理 |
| --- | --- |
| 问题成立 | P0 必须解决；P1 默认修，成本明显高于收益时说明理由；P2 按实际收益处理 |
| 事实缺失或有争议 | 调查后再决定，不用投票代替证据 |
| 需要改变业务行为或重要取舍 | 带证据、影响和建议交用户决定，沿用已有委托 |
| 只需调整表达或局部实现说明 | 直接修订并告知，不改变原批准的含义 |
| 意见不成立 | 记录拒绝理由和证据，让审阅者复核 |

未解决的核心缺口不能靠移入待决项关闭。用户批准缩小交付范围时，明确记录新的范围，检查受影响设计，不把沉默当作范围变更。

修复后按变化影响检查相关正文、附表、图、决定和任务。需要复核的修复交原审阅者；不能续用时给新审阅者原报告、当前快照和变化。审阅者仍坚持事实或影响判断时先查证；实际取舍需要用户决定时才请用户裁决。

每轮复核追加到原报告，注明对象版本或快照、实际范围、已关闭和未关闭问题、结论。首轮不通过不能在恢复会话后被口头“已修”覆盖。交付时列出保留的 P1、P2 和未完成检查。

同一问题反复修复没有新证据时，停下重查原因，不继续叠加补丁。无法取得必要证据或独立审阅时保留未完成状态，继续不依赖它的工作。
