# 任务简报

从 task 提取本轮派发简报，补上实际工作区与授权。写齐本任务必须遵守的规则、接口、协作约定和验收；附上当前 plan 与 note 供查证。简报是本轮执行输入，不另建一套长期任务文件。

```markdown
# <编号>：<可验证的能力>

## 目标与范围
用户或调用方可观察的结果：
负责的模块、仓库与可写范围：
相关项目约定与已有授权：

## 当前依据
原始需求、ADR、技术方案、任务与相关知识的内容及版本：
相关 JSON 图源、SVG 及已确认版本：
必须成立的行为、接口语义与约束：
尚未决定的问题及影响：
当前适用的实施、测试方法的位置或正文：

## 依赖与验收
依赖的接口与行为是否可实际使用：
验收场景、输入、预期结果和验证方式：
值得向用户展示的变化或关键机制：

## 工作区与交接
代码起点、已有未提交改动和其他在途工作：
执行者角色：只完成本任务，不派发子代理：
本轮结果、报告与证据的返回方式：
```

给出具体约束和来源。来源无法访问时，附上相关正文并说明限制。

用修订号、提交或内容快照确定约定和代码的版本，只给可变的路径或修改时间不够。

包含未提交、未跟踪文件时，保留修改前后的快照或等效差异；多个仓库分别记录。无需为了审阅而提交代码。
