# 编排实施任务

开始时声明：“正在使用 rivo:planning-tasks，把已确认方案拆成实施任务。”

任务文件服务执行者。把用户已经确定的方向落实为范围、契约、依赖和验证要求，保留选择理由与明确限制，避免执行者重新设计。任务组合必须完成整个需求，正文可以直接、具体，不必写成评审文章。

**plan 必须已经独立审阅和用户审阅通过。task 初稿及后续内容修订必须独立审阅；任务拆分不替代设计决定，也不产生实施授权。** 默认不要求用户逐项评审任务，用户明确要求评审时等待其确认。

## 核对依据

读取当前 plan、原始请求、用户决定、相关 note、ADR、审阅报告和实际代码。核实审阅对应当前方案；文件存在、旧报告通过或代码已经实现，都不能代替批准。

已有获批方案不论来自哪套流程都可以使用。缺少技术事实时调用 investigating；缺少业务规则或共同契约时，通过 discussing-designs 讨论，并由 writing-designs 更新方案、完成复审。不能在 task 中悄悄作出这些决定。

用宿主任务工具建立或沿用清单：核对依据、划分任务、补齐契约与验证、自查覆盖、独立审阅和交接。没有工具时在会话列短清单。

## 按可验证结果划分

每个任务交付一项可单独检查的能力。把配置、脚手架和配套测试放入需要它们的任务，不为每个文件分配一个子代理。先验证会影响后续结构的假设；存在依赖时标明先后，独立任务才能并行。

先核对所有任务共同依赖的接口和状态，再细化实施步骤。接口名、字段、类型和失败结果使用获批方案中的实际值；发现缺口时查证或带回用户讨论，不能为方便拆分另定契约。复杂点可以给伪代码或示例；普通步骤说明明确动作即可，不要求在文档里提前写完全部实现。

每个执行者都应得到本任务所需的完整约定，不能只收到“见 plan 第几节”“类似任务 1”。在任务中写出适用规则、输入输出和验收，再附原方案供查证。重复必要契约比让子代理重新猜测更可靠。

```markdown
# <需求名称>：实施任务

## 目标与共同约定
已批准方案与原始目标、适用版本、公共接口、外部依赖和已有授权。

## 任务顺序
列出各项可验证结果及依赖，覆盖整个需求。

## 任务 <编号>：<可验证结果>
目标与范围：用户或调用方能观察到什么，涉及哪些仓库。
前置依赖：依赖哪个任务或外部条件，怎样确认可用。
修改位置：新增、修改与测试的实际文件及职责。
输入输出：本任务消费和提供的接口、字段、状态与失败语义。
实施步骤：具体动作，关键处附必要代码或配置示例。
工程注意事项：从 note 提取本任务必须遵守的限制。
验证与完成标准：场景、输入、预期结果、命令或检查方式。
结果：由交付阶段记录实现、审阅和验证证据。

## 整体验证与交接
检查组合行为、外部联调、兼容和发布要求，不能只累加任务通过数。
```

## 修改与重新审阅

收到新方案、调查结果或实施反馈，先查清哪些任务受影响，包括已完成和正在执行的任务。重写相关任务的范围、步骤、契约、依赖与验证要求，清除失效安排，不在末尾追加与正文相矛盾的备注。

**任务内容变化后必须重新独立审阅，之后才能执行受影响任务。** 如果改变了设计，先取得用户决定，更新并复审 plan，再调整 task。单纯实施顺序和普通代码细节由 AI 处理，不增加一次用户批准。

已经实现的部分按新约定重新验证；旧完成记录和报告保留为历史证据，不能直接套用到新内容。只更新实施进展时核对实际证据，不用勾选项冒充审阅结果。

## 自查、独立审阅与交接

先将任务逐项对照原始目标和 plan：是否遗漏功能、是否跨任务契约矛盾、是否缺少集成验证、是否新增未批准的决定。

读取 [实施任务审阅提示词](references/task-reviewer-prompt.md)，每轮启动新的独立审阅者，报告写入 `reviews/task-<round>.md`，固定被审文件版本。修复后复审；反复无进展时补查证据或将设计分歧交给用户，不能让任务文档替用户解决模型问题。

任务覆盖完整方案、契约与依赖一致、验证可执行、当前稿独立审阅通过后，本次任务编排完成。用户已经授权实施时加载 implementing-tasks；只要求编写任务就交回文件。不要重复询问已有授权，也不能把“写 task”当作授权改代码。

## 保存位置

使用 Markdown，默认保存到本需求的 `.rivo/issues/<slug>/task.md`，与 plan 集中存放。沿用已有目录和项目约定，用户指定位置优先。写作继续使用可用的 writing-clearly-and-concisely，完整性优先于文章修辞。

task 是维护任务约定的位置。派发时可提取当前任务简报，不再维护一套需要同步的长期任务文件。原位修订当前内容，每轮审阅报告单独保留。

## 常见错误（Red Flags）

| 你在想 | 应当怎么做 |
| --- | --- |
| “任务给 AI 看，缺少一点上下文没关系” | 把执行所需规则、契约和验证写齐。 |
| “plan 没写，我在 task 里决定” | 回到设计讨论并完成方案复审。 |
| “已审过 task，调整步骤可以直接做” | 重新审阅当前任务及关联依赖。 |
| “用户不审 task，可以直接开工” | 仍须独立审阅通过并具备实施授权。 |
