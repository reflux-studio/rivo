# 实施

开始时声明：“正在使用 rivo:flow，实施已批准的技术方案。”

实施是对方案的验证。方案是否正确、是否合理，要真正照着做了才知道：接口不够用、三方库的实际表现不符合预期、性能太差，都会反过来推动方案修改。主代理写实施方案、派发任务、处理意见和偏离，执行者带着质疑完成任务，独立审阅者评估真实改动。

## 进入条件

读取需求目录 `.rivo/issues/<slug>/` 中的 plan.md、adr/、note.md，以及已有的 task.md、reviews/ 和实际改动。plan.md 顶部标为定稿，或处于修订期间且当前任务不依赖改动部分，才能实施。0.7 留下的方案没有状态标记：有批准记录或已经进入实施的视为已批准，无法确认的先问用户。

实施需要用户授权，批准方案不等于授权实施。已有的授权继续沿用，不重复索取；用户沉默或关闭提问不是批准。实施授权不包含推送、合并、发布这类不可逆操作，除非用户另外说明。

继续已有需求目录时，从 task.md 的实施记录、审阅报告和实际改动核对进度，接着已有文件写。

## 写 task.md

按 [拆分方法](references/planning.md) 写 `.rivo/issues/<slug>/task.md`：每项任务只写可验证结果、依赖、必须遵守的契约和验收方式。写完自查它是否覆盖了整份 plan.md，覆盖完整即开工，不单独送审。

## 逐任务派发与审阅

按 task.md 标明的依赖推进。

1. 按 [执行者提示词](references/implementer.md) 启动新的执行者，给它 task.md 中本任务的条目和共同约定，以及 plan.md、adr/、note.md 的位置。执行者自己读方案和代码。
2. 接收执行者的结果。执行者报告方案问题时，按 [接收意见](references/receiving-review.md) 核实，属实的按下文"偏离方案"分流。执行者列出的实现选择，也按偏离表逐条核对和处理。
3. 按 [审阅者提示词](references/reviewer.md) 启动新的独立审阅者，逐任务模式，检查本任务当前的完整改动。每轮都针对当前代码版本，旧报告不能证明新版本通过。报告写入 `reviews/<任务>-<n>.md`，n 接着该任务已有的最大编号递增，不覆盖旧报告；轮次只用于三轮上限，与文件编号分开计。
4. 按 [接收意见](references/receiving-review.md) 逐条核实审阅意见。报告里有阻塞问题时，属实的交给执行者修复，再由新的审阅者全量重审。报告里没有阻塞问题时本轮即为通过：代码中的非阻塞问题交给执行者改完并重跑本任务的验证，然后推进，不再审阅。
5. 同一任务连续三轮未通过，停下来按接收意见中的规则分析根因，报给用户，不开第四轮。

## 偏离方案

实现与方案不一致时，按偏离的对象分流：

| 偏离的对象 | 处理 |
| --- | --- |
| 某份 ADR 的决定 | 加载 confluence，由用户决定，更新决策树后修订 plan.md |
| plan.md 中写明的内容，例如行为、契约、字段、验收 | 加载 course 修订 plan.md 并全量重审，向用户说明改了什么、为什么，由用户确认 |
| 方案没有写到的纯实现选择 | 主代理决定，记进 task.md 的实施记录 |

新事实需要查证时加载 investigating。向用户说明偏离时，使用接收意见中的固定格式，不用已经写好的代码倒逼用户接受。

plan.md 修订期间，不依赖改动部分的任务继续实施，依赖改动部分的任务等方案重新定稿。重新定稿后，修订 task.md，检查已经完成的任务：受改动影响的，按新方案重新实施或验证，并重新做逐任务审阅，从第 1 轮计轮。原有的实施授权继续有效，除非用户收回。

## 整体审阅与验收

所有任务完成后，按审阅者提示词的整体模式启动新的审阅者，检查方案的整体完成度、代码整体质量和影响面。分级、三轮和接收意见的规则与逐任务审阅相同，报告写入 `reviews/final-<n>.md`。需要修复时，由主代理指派执行者修复，重跑受该修复影响的任务验证和整体验证。

整体审阅通过后，宣告交付完成，请用户验收。说明实际改动、审阅与验证结果，并列出 task.md 实施记录中被拒绝的非阻塞意见和分级异议。

用户验收时提出修改：实现没有达到方案的，修复后重新做受影响任务的逐任务审阅和整体审阅，再请用户验收；需要改变方案或决定的，按上表分流。

用户明确表示验收通过后，加载 delta 收尾。知识库和归档由 delta 负责，本技能不写。

## 修订原则

修订 task.md 和代码后，结果只陈述当前的正确做法，读起来像第一次就写对了。task.md 在原处重写受影响的任务，不在旁边追加补丁句，不因一次纠正新增"不要……"一类的否定句；实施记录是有意保留的记录，按条追加。代码直接改成正确的实现，不留下被替换的旧实现、开关或解释旧做法的注释。批量替换或改名之后，先全文自查残留再送审。

## 常见错误（Red Flags）

| 你在想 | 应当怎么做 |
| --- | --- |
| "方案这里走不通，我绕一下也能做出来" | 停下，带证据按偏离分流。 |
