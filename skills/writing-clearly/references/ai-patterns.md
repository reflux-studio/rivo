# 表达检查

判断一句话是否提供了当前读者需要的信息，而不是根据词语猜它是否由 AI 写成。

| 现象 | 编辑时检查 |
| --- | --- |
| “提高稳定性”“体验更好”等结果评价 | 是否说明了实际变化，有无支持效果判断的证据 |
| “下面分几类”“值得注意”等引导 | 删掉后结构是否仍清楚，若清楚就删 |
| 同一对象换多个称呼 | 是否会让人误以为是不同对象，统一准确名称 |
| 同一事实在段落、表格、代码中反复出现 | 选择最合适的表达位置与形式 |
| 正文展示排查经过、审阅轮数或工作量 | 是否属于当前文档目的，通常移回工作记录 |
| 每个主题都有同一组小标题 | 标题是否来自实际问题，是否在填空 |
| 句子过密或条目碎片化 | 重新组织关系，不能只靠拆短或改列表解决 |
| “一定”“全部保证”等过满判断 | 结论是否超出实际验证范围 |
| 大量“可能”“一般” | 能否说清成立条件和未知原因 |

必要的对比、因果和限定应保留。不要把检查表变成禁词表或写作模板。
