# 写清楚

先想清楚读者已经知道什么，读完要理解、判断或执行什么，再选材料。本技能只管表达；文档有哪些章节、写哪些内容，由模板和项目要求决定。

## 组织内容

- **先给结论**：开头交代主要判断或做法，再展开依据和细节
- **先总览后细节**：总览说明结果和关系，正文说明行为、条件和理由。同一主题可以在两层都出现，每次都要推进理解
- **相关的放在一起**：互相依赖的条件、动作和理由写在同一处，读者不用前后翻找
- **一段一个意思**：保留必要的因果和转折，长短由解释需要决定
- **有模板时守模板**：保持约定的章节和职责，在章节内按理解的顺序展开

## 选择表达形式

| 要表达的内容 | 适合的形式 |
| --- | --- |
| 机制、理由、取舍、条件 | 连贯段落 |
| 同类事项的比较，字段或状态的定义 | 表格 |
| 有先后的操作 | 编号步骤 |
| 精确的语法、数据格式、调用方式 | 代码或示例 |
| 结构、调用、流转和依赖 | 图 |

- **形式互相补充**：表格给出精确定义，周围文字解释含义和使用条件；图展示关系，正文写出关键结论
- **解释用段落**：不用一串碎片条目代替完整的解释
- **内容决定形式**：没有实质内容的章节一句话带过，不为整齐凑内容

## 用词与依据

- **具体**：写具体的对象和动作，保留准确的名称、数值和限制
- **名称一致**：同一对象在标题、正文、图和代码引用里用同一个名字。术语首次出现时按读者需要解释
- **分清事实、推断和设想**：未查证的判断注明缺口，不用流畅的因果句带过
- **依据可核验**：关键依据在需要核验的位置给出定位。链接用于查证，理解当前主题所需的解释留在正文
- **删掉没有信息的话**：空泛的评价、重复的提醒、与阅读任务无关的背景

## 图

按要表达的关系选图：

| 关系 | 图 |
| --- | --- |
| 结构与分层 | 架构图 |
| 步骤与分支 | 流程图 |
| 跨角色、跨系统的交互 | 时序图 |
| 生命周期 | 状态图 |
| 实体与依赖 | 关系图 |

- **回答一个具体问题**：图的范围和细节以读者当前要理解的问题为界
- **分清现状与目标**
- **适配阅读环境**：能渲染图形时展示渲染结果；纯文本环境用简洁的文本图，或提供可打开的文件
- **工具按项目约定**：没有约定时用当前环境可用的方式
- **检查实际显示**：生成或修改后查看文字、连线和布局，并与正文核对。语法通过不等于显示正确，无法查看时说明未做视觉检查

## 修订

- **在原处写成当前的说法**：读起来像第一次就写对了
- **清理衍生内容**：一个假设被纠正后，删掉由它引出的解释、对比和示例
- **不留纠错痕迹**：不为说明“已经改正”而增加否定句。修改过程写在文档约定的修订记录里
- **改名后查残留**：调整标题或术语后，检查相关的图、表、引用和目录

## 通读检查

- 读者能否先建立整体认识
- 相关的条件和理由是否在一处
- 总览和细节是否各有作用
- 图表是否帮助理解
- 结论是否有依据
