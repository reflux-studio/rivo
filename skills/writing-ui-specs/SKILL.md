# 撰写界面设计方案

把界面的设计意图写成完整的施工规格：写代码的人不需要猜任何一个间距、任何一个状态。

## 工作流程

### 1. 理解输入

输入可以是任何形态：

- **设计稿**：Figma 链接、截图、本地 HTML。若已连接设计工具，拉取精确的尺寸、token 和组件信息。
- **文字描述**：「订单列表要加一个批量导出入口」。
- **没有稿**：从需求出发，由你依据设计系统先做设计决策，再落成规格。

同时判断规模：规格的深度与界面变化量成正比。只加一个按钮状态的改动，只写涉及的节——空节是噪音，不是完整性。

### 2. 依据设计系统

- 若项目里维护着长期设计文档（token、组件库、断点、业务组件清单一类），从那里引用，不重新发明。
- 引用 token 而不是裸值：写 `spacing-md`，不写 `16px`。
- 设计系统解决不了的，才引入新样式，并写明为什么现有的不够用。

### 3. 组件选型与拆分

把界面拆成组件的组合，每一块按优先级做三层匹配：

1. **业务组件优先**：先对照设计文档里的业务组件清单（订单卡片、客户选择器这类），认出来就直接引用。
2. **组件库的高级组件次之**：ProTable、ProForm 这类约定大于配置的封装，能覆盖就不用基础组件自己拼。
3. **基础组件兜底，自定义最后**：都不行才新建，写明为什么现有的不够用，并判断它该不该沉淀为新的业务组件、进入设计文档。

选型是设计决策——选 ProTable 还是 Table，决定的是筛选、分页、工具栏的整套交互模式。选型理由不显然时，写出来。

### 4. 撰写规格

按「应包含的内容」逐组检查，按「产出结构」组织成文。

### 5. 自查与交付

- 对照下面的四条原则自查一遍。
- 把你拿不准、需要用户拍板的设计决策单独列出来。
- 若这单工作有自己的工单目录，文档存为其中的 `ui-spec.md`；否则按用户指定的位置保存。

## 应包含的内容

### 视觉规格

有可访问的设计稿时，这一组只记两样：区块对应的稿件节点链接，和偏离设计系统或组件库默认值的点。没有稿（文字需求直出、由你先设计）时才需要写全：

- 精确尺寸：内边距、外边距、宽度。
- 设计 token 引用：颜色、字体、间距。
- 响应式断点与各断点下的行为。
- 组件的变体与状态。

### 交互规格

- 点击/触碰行为。
- 悬停状态。
- 过渡与动画：时长、缓动函数。
- 手势支持：滑动、捏合、长按。

### 内容规格

- 字数限制。
- 截断行为。
- 空状态。
- 加载状态。
- 错误状态。

### 边界情况

- 最少/最多内容。
- 国际化文本（更长的字符串）。
- 慢速网络。
- 数据缺失。

### 无障碍

- 焦点顺序。
- ARIA 标签与角色。
- 键盘交互。
- 屏幕阅读器播报。

## 原则

1. **设计稿是视觉细节的事实源**——稿上能查到的值不抄进文档：抄一份就是双写，设计稿一改文档就开始撒谎。文档记录节点链接和稿上表达不了的东西，实现的人对着稿实时查（设计工具的开发模式或接入的设计工具连接器都支持）。
2. **不留假设**——没写明也没稿可查的地方，开发者只能猜。把一切写明或给出去哪查。
3. **用 token，不用裸值**——引用 `spacing-md`，而不是 `16px`。
4. **展示所有状态**——默认、悬停、激活、禁用、加载、错误、空。设计稿通常只画理想态，其余状态由文档补齐。
5. **解释为什么**——「移动端折叠这一栏，因为用户主要单手操作」能帮开发者在没覆盖到的地方做出正确判断。

## 产出结构

```markdown
## 界面设计方案：[功能/页面名]

### 概述
[这个页面/功能做什么，用户在什么场景下使用]

### 设计稿索引
| 区块 | 稿件节点 |
|------|---------|
| [列表区] | [Figma frame/node 链接] |
| [筛选栏] | [链接] |

（实现时对照稿件实时取值；没有设计稿则删除本节，视觉细节写进下面各节。）

### 布局
[栅格系统、断点、响应式行为]

### 组件结构
```
页面
├── 筛选栏（ProForm QueryFilter）
├── 订单列表（ProTable）
│   └── 订单状态列（业务组件 OrderStatusTag）
└── 批量操作栏（自定义，理由见备注）
```

### 组件
| 组件 | 来源 | 变体与配置要点 | 状态与行为 | 备注 |
|------|------|--------------|-----------|------|
| [组件名] | [业务组件 / 组件库 / 新建] | [变体、关键配置] | [各状态下的表现] | [选型理由、特殊行为] |

### 使用的设计 Token
（有设计稿时只列偏离设计系统默认的项；无稿时列全。）

| Token | 值 | 用途 |
|-------|-----|------|
| `color-primary` | #[hex] | 主按钮、链接 |
| `spacing-md` | [X]px | 区块间距 |
| `font-heading-lg` | [字号/字重/字体] | 页面标题 |

### 状态与交互
| 元素 | 状态 | 表现 |
|------|------|------|
| [主按钮] | 悬停 | [背景加深 10%] |
| [主按钮] | 加载中 | [转圈，禁用] |
| [表单] | 错误 | [红色边框，下方错误信息] |

### 响应式行为
| 断点 | 变化 |
|------|------|
| 桌面（>1024px） | [默认布局] |
| 平板（768-1024px） | [变化点] |
| 移动（<768px） | [变化点] |

### 边界情况
- **空状态**：[没有数据时展示什么]
- **超长文本**：[截断规则]
- **加载**：[骨架屏还是转圈]
- **错误**：[错误状态的外观]

### 动效
| 元素 | 触发 | 动画 | 时长 | 缓动 |
|------|------|------|------|------|
| [元素] | [触发条件] | [描述] | [ms] | [缓动函数] |

### 无障碍说明
- [焦点顺序]
- [需要的 ARIA 标签]
- [键盘交互]
```

组件表描述的是外观与行为——各状态下长什么样、做什么；组件的代码接口（Props、事件、类型）属于技术方案，由工程定义。

## 注意事项

- **有设计稿链接就用**：若已连接设计工具，拉取精确尺寸、token 和组件信息，不靠目测。
- **主动追问边界**：「列表有 100 条数据时怎样？」——边界条件不会自己出现在设计稿里。
- **落在既有体系上**：规格里的断点、组件名与项目的设计系统一致，工程才能直接对上。
- 定稿后再改，改动要重新走评审，不口头补充新说法。
