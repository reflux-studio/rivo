# 委派子代理

委派者负责边界、整合与结果核验。子代理继承当前角色的权限，不因新会话获得其他产物的修改权。

## 流程

1. 判断独立上下文、并行或审阅的收益是否超过交接成本。当前工作明确要求独立审阅时保留该要求；短小且无需独立判断的工作可直接做。
2. 核对用户偏好、项目约定与实际可选配置。未指定时按任务难度、错误代价、成本和延迟选择；配置固定时沿用，不虚构模型或修改主会话设置。
3. 给出目标与验收、原始输入及版本、可读/可写范围、已有授权、依赖、返回产物和验证边界。有适用提示词就使用，独立审阅者不得参与被审实现。
4. 不同执行者不并发修改同一文件或环境。负责人、依据和下一步记录在当前任务已有的安排中；只有共享工单登记的真实参与方才可按 collaborating 跨角色联系，临时子代理不自动成为产品/测试负责人。
5. 查看真实文件、差异、证据与工具结果，不凭“已完成”口述判断。静态、模拟、实际运行及未执行分别说明；整合后验证公共契约与影响面。
6. 缺信息补材料，环境受阻说明解除条件，能力不足时拆小或使用允许的更合适配置。仅暂停依赖问题的工作，不重复同一失败充作升级。

子代理不可用时继续不依赖它的工作并报告限制，自查不算独立审阅。材料和结果位置由当前工作约定，不强制创建某个领域的文件。
