# 开发工作

需要 rivo-development。读取用户给定需求与设计，核对实际代码、团队规约和授权；材料可以由人类同事提供，不依赖其他领域插件。

| 工作 | 领域技能 | 结束于 |
| --- | --- | --- |
| 核对需求的技术含义、依赖和重要选择 | converging | 技术做法与未定业务问题分清 |
| 写技术方案并组织审阅 | writing-plans | 方案确认；开工仍需实施授权 |
| 逐任务实现、自测和独立审阅 | implementing-plans | 可提测的实现、自测结果与限制 |
| 定位异常 | systematic-debugging | 有证据的原因及验证结果 |
| 用失败测试驱动行为实现 | test-driven-development | 行为与回归验证完成 |

技能按 rivo-development 的实际发现位置加载。批准或已有授权覆盖时继续，不重复询问。业务歧义、产品规则变更交需求负责人；开发不修改他人的需求、测试用例或质量报告。测试可以来自人类或既有团队，不强制启动测试插件。

## 默认产物位置

| 位置 | 用途 |
| --- | --- |
| development/decisions.md、development/adr/ | 技术决定、问题与重要取舍理由 |
| development/research/ | 技术事实及原始材料 |
| development/plan.md、development/assets/ | 当前有效技术方案与附件 |
| development/task.md | 任务归属、进展、自测与提测安排 |
| development/reviews/ | 方案、逐任务及整体审阅 |
| development/evidence/ | 开发自测及定位证据 |

相对需求目录，用户或团队位置优先。代码及开发单元测试留在目标仓库惯用位置，登记实际工作树。设计来源由任务/方案引用；实施者实际对照设计，审阅者核对还原度，不设独立设计还原技能。

技术职责、契约来源或扩展点等重要选择在扩散前明确。完成后报告实现版本、开发自测和提测前提，不把它写成独立测试通过；收到缺陷后修复本人代码，再提供可复验版本。
