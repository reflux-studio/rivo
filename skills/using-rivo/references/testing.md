# 测试工作

需要 rivo-testing。读取用户给定需求、设计、接口和待测对象，确认实际版本与可用环境；不要求先运行产品/开发插件或提供完整源码。

| 工作 | 领域技能 | 结束于 |
| --- | --- | --- |
| 分析风险与设计用例 | designing-tests | 可观察预期、覆盖和执行前提明确 |
| 实际执行与探索、复测回归 | testing | 对应版本的结果、风险与缺口 |
| 记录并反馈缺陷 | reporting-defects | 可复现记录及真实的交接状态 |

技能按 rivo-testing 的实际发现位置加载。E2E是执行方式之一，不代表整个测试工作。测试可以帮助定位问题，但产品实现交开发修改；预期有歧义交需求负责人，不能为匹配实现改预期。重要用例失败、受阻或未执行时不报整体通过。

## 默认产物位置

| 位置 | 用途 |
| --- | --- |
| testing/plan.md | 测试范围、风险、环境与执行安排 |
| testing/cases.md | 场景、输入、操作与预期 |
| testing/defects/ | 缺陷正文与证据引用 |
| testing/runs/<运行编号>/ | 每次实际执行报告、日志与截图 |
| testing/scripts/ 或目标仓库指定位置 | 测试负责的验收/回归脚本 |

相对需求目录，用户或团队位置优先；用例与运行结果分开维护。已有测试系统可直接引用，不复制一套缺陷状态。对已登记开发方发协作请求，详细缺陷不进工单；修复后核对版本再复测原问题及影响面。质量结论与是否接受交付分开，接受剩余风险由有权人决定。
