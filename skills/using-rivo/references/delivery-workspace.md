# 交付工作区约定

供主线程首次组织材料、恢复交付或接续旧版时使用。以下为默认位置；已有文档、任务系统或用户约定优先。方法技能接收实际位置，不要求项目采用此结构。

```text
.rivo/
├── knowledge/
│   ├── README.md                  # 导航；小项目可直接记录知识
│   └── <topic>/README.md          # 业务、产品、应用或工程主题
├── issues/<slug>/
│   ├── spec.md                    # 需求与交互约定
│   ├── ADR.md                     # 重要决定，可按编号拆分
│   ├── system-design.md           # 技术方案，复杂时链接模块附属文档
│   ├── progress.md                # 长任务的当前状态与恢复入口
│   ├── tasks/                     # 需要持久化的任务简报
│   ├── reviews/                   # 各轮独立审阅与碰撞记录
│   ├── evidence/                  # 日志、截图、运行证据
│   └── assets/                    # 原始输入或图源，按需
└── archived/<slug>/              # 完成交付的材料
```

按实际内容创建，不生成空目录或占位文件。外部 PRD、设计稿、接口契约已有权威来源时引用即可。保留清晰的人类阅读入口，文件数不作为流程完成标准。

## 内容归属

- Spec：需求范围、行为、UI 形态、规则、验收和待定项，可引用现有 PRD。
- ADR：重要选择、依据、代价与替代关系，不记录每个常规实现决定。
- 技术方案：总体做法、组件和模块、复用分析、接口、数据、影响、验证与发布安排。
- 知识库：可复用的当前结论与依据；计划能力和未确认判断保留在交付材料中。
- 审阅和证据：保留原始版本，不用新结果覆盖旧轮次假装一次通过。

## 长任务恢复

长任务从需求澄清起建立进度记录，保存目标与授权范围、当前阶段、已定结论、未决问题、依据与版本、材料入口和下一步。阶段转换或重要决定变化时更新；实施后再补已完成／执行中／待审／待决定的任务及在途代理。已有任务系统能保存同等信息时直接使用，小任务不强制另建文件。

恢复时核对记录与当前工作区、任务状态及最新决定，再继续下一步。任务简报引用可识别的修订、快照或提交，避免只凭可变路径派发旧契约。

## 归档与旧版兼容

完成交付后可将该任务目录移入 archived，修复知识库、导航、相对链接及图表依赖。尚未完成的发布或交接项应保留明确状态，不能靠归档表示完成。

旧项目使用 `.rivo/models/` 时，先把它作为已有知识来源。不要自动搬空旧目录或新建竞争副本。用户要求迁移时，按内容合并到 knowledge，保留历史决定、修复引用，并为仍被使用的旧入口提供转向说明。

旧名称 collaborative-modeling 的需求澄清职责对应 requirements-clarification，领域方法对应 domain-modeling；capturing-knowledge 对应 knowledge-management。旧交付记录可保留原称谓，继续任务时按当前职责选择方法。
