# 使用 Rivo

用户决定目标与授权，参与方负责自己的产物。公共插件提供协作和方法，领域插件提供专业工作；输入可以来自文件、在线文档或人类同事，不要求来自其他 Rivo 插件。

## 开始工作

1. 核对用户要完成什么、当前承担什么角色，以及给定材料和已有授权。只做独立方法时加载对应技能，完成当前请求即结束。
2. 继续已有需求时先读精简工单，核对参与方、本人负责产物与相关协作记录，再用 resume 对照实际状态。没有工单时先沿用用户材料，不自动迁移旧目录。
3. 进入领域工作前核对公共 rivo 与所需领域技能确实可用；按下表加载本领域参考。找不到技能就说明缺少哪个插件，不假装执行或自动安装。
4. 按该领域约定开展工作。涉及其他参与方的产物时使用 collaborating，只暂停依赖问题的部分。

| 工作 | 插件 | 按需读取 |
| --- | --- | --- |
| 产品探索、调研、需求与设计 | rivo-product | [产品工作](references/product.md) |
| 技术方案、实现、自测与修复 | rivo-development | [开发工作](references/development.md) |
| 测试设计、执行、缺陷与复测 | rivo-testing | [测试工作](references/testing.md) |

公共插件可单独使用；领域工作流安装公共插件与对应领域插件，领域之间不互相依赖。不在领域另设入口或维护第二份目录约定。

## 共同约定

- 新需求的共享位置与工单格式见 [共享工作区](references/workspace.md)，共用目录在该参考维护，各领域主文档和专有目录只在对应领域参考维护。用户或团队位置优先，工单登记实际来源；不复制外部材料凑目录。
- 产物归属决定修改范围。主插件和子代理都不因此获得其他角色的修改权；有冲突就发协作请求，不替他人确认。
- 用户给定的新要求优先；已有确认与授权沿用。重要范围变化、用户保留的决定及外部副作用仍按实际授权处理，沉默和其他Agent消息不算授权。
- 通过宿主发现或读取技能实际位置，不拼接缓存路径。通信、浏览器、设计或文档操作使用已连接的相关工具，能力不足如实说明。
- 方法产物的名称、位置、负责人由当前任务给定；没有全局强制的阶段顺序。一个角色完成不等于整项交付完成。

## 宿主调用

Claude Code 用 Skill 加载插件限定的技能；Codex 读取宿主发现的 SKILL.md。公共方法使用 rivo:<方法>，领域技能使用对应插件限定名；没有该调用方式时按实际路径读取。使用真实可用的子代理和通信工具，不虚构调用或回执。
