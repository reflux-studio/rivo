# 使用 Rivo

Rivo 帮用户把需求变成可以评审的做法，再完成实施、验证和知识整理。从当前任务所在的位置开始，不要求重走已经完成的阶段。首次进入或切换技能时，简短说明本次要做什么，不照念固定开场。

## 谁处理什么

| 内容 | 处理方式 |
| --- | --- |
| 技术事实、依赖能力、现有行为 | AI 查证，区分代码推断、实验和真实运行 |
| 需求范围、可观察的业务行为、重要取舍 | 用户决定；明确委托 AI 的范围按委托处理 |
| 不改变上述约定的局部实现 | AI 在授权范围内选择、实现和验证 |

重要取舍会改变公共契约、权限边界、数据所有权，或带来显著成本和迁移负担。普通选择不会因为有多个选项、写进过文档或改动时需要返工，就自动成为重要取舍。

沉默不是批准。方案批准与实施授权分别识别，用户可以一次给出两者；已有授权继续有效。推送、合并、发布和外部写入按用户已有授权处理，不从“完成需求”推导额外权限。

## 按当前工作进入

| 当前需要 | 技能 | 完成的含义 |
| --- | --- | --- |
| 明确范围、解决设计取舍 | converging | 场景和关键决定足以支持设计，用户理解一致 |
| 写或修订供人评审的方案 | writing-plans | 当前设计经适用范围的独立审阅和用户确认 |
| 实施已批准的范围 | implementing-plans | 验证、审阅完成，用户验收 |
| 维护已核实的知识、交付收尾 | knowledge-management | 知识已更新，交付材料已归档 |

调查用 investigating，写作用 writing-clearly，行为实现用 test-driven-development，定位异常用 systematic-debugging。方法技能完成后回到原任务，不另起一套进度。

## 变化怎样处理

先确定事实，再判断影响。事实未知就调查；需要改变用户决定就带着证据和选项讨论；局部实现调整由 AI 处理。处理权限取决于变化本身，不取决于它被写在 ADR、plan 还是 task 中。

初次设计尚未批准时，不开始产品实施。实施中发现问题，只暂停依赖该问题的任务，继续已有批准和授权仍覆盖的工作。新决定确定后，同步修订受影响的方案、任务和验证。修订不撤销无关工作的授权。

审阅结论只覆盖实际检查过的内容和版本。首次方案、整体交付做独立审阅；之后按变化影响复核，纯表达修改不重审。每轮结果都保存在报告中，说明对象、版本、检查范围、结论和未关闭问题。自查不能称为独立审阅。

## 工作材料

需求材料默认放在目标项目的 `.rivo/issues/<slug>/`，用户或项目指定的位置优先。

| 材料 | 用途 |
| --- | --- |
| note.md | 原始需求依据、确认的范围、查证结果；讨论期间暂存尚未成文的决定 |
| adr/ | 值得长期保留的重要选择及理由 |
| plan.md | 本期怎样做，以及实现和联调必须共守的契约 |
| task.md | 可验收任务、依赖、实施与验证记录 |
| reviews/ | 带版本和范围的审阅与复核结论 |
| evidence/、assets/ | 验证证据、图和图源 |

继续会话时核对用户决定、文档、审阅和实际改动，不能仅凭状态行或文件存在判断完成。没有必要新建中心状态文件。需求验收后更新项目已有知识库，默认位置是 `.rivo/knowledge/`；需求目录归档到 `.rivo/archived/`。

## 宿主能力

Claude Code 用 Skill 加载 `rivo:<技能名>`，Codex 读取对应 SKILL.md；参考文件按当前步骤需要读取。技能内的文件导航用于 AI 加载指令，不是人类方案的阅读结构。

独立审阅使用宿主子代理，模型沿用宿主配置。执行可委派给子代理，也可由主代理在同一任务边界内完成；并行任务不得争用同一修改范围。提问与进度使用宿主现有工具，没有专用工具时用会话表达。

子代理暂不可用时，继续不依赖它的准备、调查或已授权实施，保留待审对象和证据。明确报告独立审阅尚未完成，不自行降低交付标准。用户选择其他审阅方式时，记录实际方式和覆盖范围。能力故障不要求重新取得已有授权。
