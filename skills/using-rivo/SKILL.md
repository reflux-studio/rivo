# Using Rivo

## 纪律

加载技能再动手。相关技能存在时必须加载并遵循，不能因为"已经理解流程"而跳过。

**写入产物前先对齐。** 需求、设计、决策类技能的第一个输出是发现和问题，不是文档。在用户回应前，不得写入 spec.md、plan.md、ADR 或其他交付产物。调查可以继续，产物写入必须等。

**授权按事项计。** "帮我做这个需求"是启动授权，不是全程免审。每个需要用户判断的问题单独获得回应。"明确委托"仅指用户针对具体问题说过"你自己定"或"不用问我"，而非泛泛的任务指派。

**产物位置由技能默认值或用户指定决定。** 已有文件的位置不构成约定；只有用户在对话中指定或项目配置文件（CLAUDE.md 等）中声明的路径才算。

只请求评审、整理或局部问题时完成该范围，不自动扩展为完整交付。已有充分依据可直接进入后续工作，小改动无需补齐所有文档。

建模贯穿需求、设计与实现，不是独立阶段。独立能力按问题使用，不作为必经环节。

用户指令（CLAUDE.md 等）优先于技能约定。

## 你正在合理化的信号

以下念头出现时，停下来——你在给自己找理由跳过流程：

| 你在想 | 实际情况 |
| --- | --- |
| 「用户说了走流程 = 全程授权」 | 启动授权 ≠ 产出授权。每个判断点单独等回应。 |
| 「先把材料看全再一起对齐」 | 技能要求发现问题就展示，不是攒到最后。 |
| 「这活儿已经很明确了」 | 明确意味着对齐会很快，不意味着可以跳过。 |
| 「用户说'你看着办'」 | 除非针对具体问题说的，否则不是委托。 |
| 「先出个草稿再讨论效率更高」 | 用户明确要求时才做，不是默认模式。 |
| 「项目里已有类似目录结构」 | 已有文件位置不是约定。用技能默认路径。 |
| 「这个太简单不需要先问」 | 简单意味着对齐只需一句话，不意味着跳过。 |
