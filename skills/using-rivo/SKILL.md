# Using Rivo

<SUBAGENT-STOP>
如果你是被主线程派发的执行者或审阅者，忽略此技能。你的任务和方法由派发提示词提供。
</SUBAGENT-STOP>

让可工作的软件与负责人的理解一起演进。承担调查、实现和验证，把重要取舍和实现中的新发现带回协作。

## 从当前任务出发

理解用户要完成什么、负责到哪里，以及已确认的规则、决定和授权。复用已有材料，区分业务目标、实现事实和待验证假设。

根据变化范围、陌生程度和风险选择工作深度。已有充分依据的阶段直接沿用。用户只要求分析时完成分析，不进入实施。

## 选择方法

按需加载，不预先读完所有技能。平台显示命名空间时使用它提供的名称；方法技能也可以单独调用。

| 当前需要 | 方法 |
| --- | --- |
| 理解业务、现状与目标变化 | [collaborative-modeling](../collaborative-modeling/SKILL.md) |
| 选择重要结构、技术或责任边界 | [architecture-decisions](../architecture-decisions/SKILL.md) |
| 形成可评审、可协作的技术方案 | [system-design](../system-design/SKILL.md) |
| 分段实施、独立审阅与碰撞处理 | [incremental-delivery](../incremental-delivery/SKILL.md) |
| 以可观察行为驱动实现 | [test-driven-development](../test-driven-development/SKILL.md) |
| 从异常定位原因 | [systematic-debugging](../systematic-debugging/SKILL.md) |
| 留下跨交付可复用的知识 | [capturing-knowledge](../capturing-knowledge/SKILL.md) |

常见路径：建模 → 架构决策 → 技术方案 → 循环实施与审阅 → 沉淀归档。重要决定用 ADR 保留理由；方案明确稳定契约，实施细节随切片展开。

## 交付材料

默认用项目中的 `.rivo/` 管理；用户指定位置或项目已有约定优先。

```text
.rivo/
├── models/<domain>/     # 跨交付领域知识
├── issues/<slug>/       # 目标、决定、方案、任务简报、审阅与证据
└── archived/<slug>/     # 完结归档
```

把实际位置传给方法技能，方法技能不需要认识 `.rivo`。按实际需要创建文件，不生成空目录或占位文档。已有任务系统能持久保存同等信息时直接复用。

## 保留人的判断

在新的业务语义、重要取舍或意外行为处安排讨论。让用户解释预期、比较后果或追查证据；按问题选择一种有用的参与方式，不把每轮变成考试。

用户不知道时，先提供事实和解释，再帮助判断。用户明确委托的决定可以代为完成，说明关键依据。沿用用户已有选择，不为每个阶段重复索要许可。

## 把碰撞带回用户

实现与已确认模型、ADR、技术方案不符时，主线程必须向用户呈现具体分歧，不能只在后台修复或改文档使其看上去一致。

- 代码误实现了仍有效的规则：说明偏差，按原决定修复，无需重批。
- 规则矛盾或重要假设失效：与用户对齐；未获决定时暂停依赖它的任务。
- 证据不足：先调查，保持未确定，不把猜测升级为事实。

对齐后更新相关材料，保留旧理由，重发受影响任务的上下文。

## 完成交付

组合验证各切片，核对原始目标、兼容性及发布依赖。主线程确认阻塞发现已解决、重要分歧已有处理依据，再完成授权范围内的交接。

**更新领域全景。** 通过 [capturing-knowledge](../capturing-knowledge/SKILL.md) 将本次确认的业务规则、推翻的假设和新增的概念合并回领域全景文档。这不是可选步骤——交付改变了对业务的理解，全景文档必须反映这些变化，否则下次交付将基于过时的认知开始。
