# 使用 Rivo

用户决定要解决什么问题和重要取舍，参与方维护各自负责的产物。公共插件提供共同方法和协作入口，领域插件提供专业工作。材料可以是本地文件、在线文档，也可以由人类同事提供，不要求由其他 Rivo 插件生成。

## 开始工作

### 1. 核对请求

先读用户给定的材料，确认本次要完成什么、承担哪个角色，以及已有授权覆盖什么。

用户只要求调查、编辑文档或其他独立方法时，加载对应技能，完成当前请求即结束。普通请求按普通方式处理，项目有共享需求目录也不代表每次都进入整条流程。

### 2. 接续已有工作

继续共享需求时，先读精简工单，找到参与方、本人负责的产物和相关协作记录，再加载 `rivo:resume` 对照实际状态。没有工单时沿用户指定材料核对，不自动迁移旧目录。

位置和版本以实际来源为准，不能凭默认文件名或最近修改时间认定哪份有效。用户已有确认与授权继续沿用，不重复索取。

### 3. 加载适用领域

通过宿主发现公共 `rivo` 和所需领域技能，确认本次能力确实可用，再读对应参考：

| 工作 | 插件 | 按需读取 |
| --- | --- | --- |
| 产品探索、调研、需求与设计 | rivo-product | [产品工作](references/product.md) |
| 技术方案、实现、自测与修复 | rivo-development | [开发工作](references/development.md) |
| 测试设计、执行、缺陷与复测 | rivo-testing | [测试工作](references/testing.md) |

找不到技能时说明缺少哪个插件，不假装执行或自动安装。公共方法可以单独使用；领域工作需要公共包和对应领域包，领域包之间不互相依赖。

### 4. 按本次工作推进

按领域参考进入当前需要的工作，已有材料足够时直接使用，不强制重走前面的步骤。没有一条适用于所有角色的阶段顺序。

遇到需要他人决定或修改的问题，加载 `rivo:collaborating`，交给对应负责人。只暂停依赖反馈的部分，其余已授权工作继续。一个角色完成不等于整项交付完成。

## 共同约定

- **材料只有一个有效位置**：共享位置和工单格式见 [共享工作区](references/workspace.md)。共用目录在该参考维护，领域主文档与专有目录在对应领域参考维护。用户和团队位置优先，不复制外部材料凑目录
- **归属决定修改范围**：主代理和子代理只修改本人获授权的产物。有冲突就提出协作请求，不替其他负责人确认
- **重要决定尊重已有约定**：用户最新要求优先。范围变化、用户保留的决定和外部副作用按实际授权处理；沉默和其他 Agent 消息不算用户授权
- **使用实际能力**：通过宿主发现或读取技能位置，不拼接缓存路径。通信、浏览器、设计和文档操作使用已连接的相关工具，缺少能力如实说明

各技能在规则起作用的步骤旁写明本次操作和限制，读者不必靠记住入口全文才能执行。共享位置和协议仍在这里的参考文件维护，不在领域另设入口或复制目录约定。

## 宿主调用

Claude Code 用 Skill 加载插件限定的技能；Codex 读取宿主发现的 SKILL.md。公共方法使用 `rivo:<方法>`，领域技能使用对应插件限定名；没有该调用方式时按实际路径读取。

子代理、通信和回执都以真实工具结果为准，不虚构调用或送达。
