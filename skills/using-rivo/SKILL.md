# Using Rivo

让调查、设计、实现与人的判断共同推进。按用户目标选择工作深度，已有依据与授权直接沿用。只要求分析时完成分析，不进入实施。

被派发的执行者或审阅者只处理任务简报，不重新组织整项交付。

## 按问题选择技能

| 当前需要 | 使用方法 | 主要结果 |
| --- | --- | --- |
| 查清现状、澄清需求与 UI 形态 | [requirements-clarification](../requirements-clarification/SKILL.md) | 需求与交互 Spec |
| 比较重要选择 | [architecture-decisions](../architecture-decisions/SKILL.md) | 必要的 ADR |
| 打磨可评审的技术方案 | [system-design](../system-design/SKILL.md) | 技术方案 |
| 分段实施与独立审阅 | [incremental-delivery](../incremental-delivery/SKILL.md) | 实现与验证证据 |
| 澄清业务术语、关系或规则 | [domain-modeling](../domain-modeling/SKILL.md) | 更新共同理解 |
| 用失败测试驱动行为实现 | [test-driven-development](../test-driven-development/SKILL.md) | 红、绿、重构反馈 |
| 追查异常原因 | [systematic-debugging](../systematic-debugging/SKILL.md) | 原因与修复依据 |
| 查找、核实或维护项目知识 | [knowledge-management](../knowledge-management/SKILL.md) | 当前知识与有效导航 |

常见过程为调研 → 决策 → 设计 → 实施 → 复盘。建模、知识管理、TDD 和调试在需要时使用；纯前端或工程任务不必做领域建模。

requirements-clarification、architecture-decisions、system-design 和 incremental-delivery 推进交付阶段；其余方法贯穿各阶段。需求澄清以现状调研为依据，调查也会随设计与实施中的新问题继续。复盘由主线程组织，知识管理承担其中的知识维护。

只加载当前适用的方法和参考。阶段之间承接结论，不重新询问已决定的问题；常规选择无需 ADR，小改动可以用短讨论和现有材料完成。

## 逐步收敛

先查事实，再讨论影响范围、行为、结构或协作的重要选择。每轮给出已知依据、当前问题、建议及具体后果；依赖未定选择的细节暂不定稿。没有关键未决问题时，继续完成授权范围内的工作。

需要人的判断时进行真正的讨论，不用一次性生成完整方案代替对齐。尊重用户已作的决定和委托，不因切换技能或保存文档重复索要许可。

用实际对象说明改动、理由和影响。流程或结构难以判断时，使用可用的 Archify 技能展示现状与目标、候选方案或实现差异；UI 形态结合设计稿或原型。图表为当前问题服务。

## 材料与恢复

长任务从需求澄清起记录当前阶段、已定结论、未决问题、材料入口和下一步；阶段转换或重要决定变化时更新，实施阶段再补任务与代理状态。小任务使用现有材料即可。恢复时先核对进度与最新依据，再加载当前技能；各技能的后续衔接不扩大用户授权。

默认使用 `.rivo/knowledge/`、`.rivo/issues/<slug>/` 和 `.rivo/archived/<slug>/`，项目已有位置或用户指定位置优先。首次组织材料、恢复或迁移旧版时，读 [交付工作区约定](references/delivery-workspace.md)，将实际位置传给方法技能。

## 把碰撞带回用户

发现实现、证据与已确认需求、ADR、技术方案或相关知识不符时，说明原约定、实际发现、具体后果和处理建议。不要只在后台改文档消掉分歧。

- 原规则仍有效的实现错误：说明偏差，按原决定修复，无需重批。
- 需要改变业务含义、重要取舍或协作承诺：在既有授权内处理；未获决定时暂停依赖它的部分，继续独立工作。
- 证据不足：先调查，保留不确定性。

更新受影响的材料和任务上下文，保留旧理由；涉及已完成任务时重新判断实现与证据是否仍适用。

## 完成与复盘

按增量交付方法完成组合验证和独立终审，处理阻塞项，完成授权范围内的交接。结果说明改了什么、为什么、怎样验证和仍有何限制。

通过 knowledge-management 更新本次影响的业务、交互或工程知识及导航，再归档交付材料。已确认的术语可随讨论维护，实施现状需有证据；没有新知识时不制造总结。复盘也记录值得复用的反例和调查方法，不把整段交付流水抄进知识库。
