# 测试驱动开发

开始时说明正在使用 `rivo:test-driven-development`，并用一句话说明本次要做什么。同一项工作中不重复声明。

先运行测试，看见它因目标行为缺失而失败，再写实现。测试未运行，或因环境、编译问题而中断，都不能证明它检验了目标行为。

围绕用户或调用方能观察到的行为推进，每轮只处理一个行为。测试与实现的进度沿用当前任务。

## 流程

### 1. 选择下一项行为

- 预期来自需求、接口约定或可复现的缺陷，不照着待测代码反推
- 测试不替业务做决定
- 预期不明确或互相冲突时，暂停该行为的实现，向主代理报告原约定和冲突；单独使用时请用户决定

选择测试层级：
- 能验证目标行为的层级，优先沿用已有测试的范围和边界
- 只模拟本次范围以外的依赖
- 检查结果和承诺的行为，不复制实现算法，也不只检查调用了 mock

### 2. 红

1. 写出表达这项行为的测试
2. 运行，确认它因行为缺失而失败
3. 意外通过时，检查测试能否区分错误行为

### 3. 绿

1. 写满足该行为的最小合理实现
2. 运行相关测试，实际通过才进入下一步

### 4. 重构

1. 在测试保护下改善结构
2. 再验证受影响的行为
3. 测试没通过先解决，不进入下一个行为

保持每轮改动足够小，失败时容易定位。修复缺陷时，保留能重现原问题的回归测试。

## 适用边界

- 视觉改动用视觉检查，文案用审校，环境配置用相应验证；如实说明用的是什么方法
- 区分模拟、集成与运行环境的证据，报告未覆盖的范围
- 已有检查通过后，只有新改动或未解决的问题才需要重复测试
- 遵循用户明确的验证范围

## 报告结果

- 实现和实际验证结果
- 未覆盖的范围

测试通过后，继续完成当前任务要求的验收和审阅。
