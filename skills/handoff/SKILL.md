# 交接

阶段收尾时，把「接手的人需要知道什么」写进交接纪要；下一阶段开新会话，凭它快速接手，省去通读全部产物反推现状的成本。

若 [using-rivo](../using-rivo/SKILL.md) 总纲尚未在上下文中，先读它。

## 写交接

读 [handoff.md](templates/handoff.md) 模板，更新 `.rivo/issues/$issue_id/handoff.md`——单文件滚动更新：每次整体重写，删掉已过时的内容。

写四类东西：

1. **当前进度**：刚结束什么、结果如何、下一步是哪个阶段。
2. **关键决策的指针**：一句话 + 指向产物的章节 / 条目编号，让接手的人知道去哪细读。
3. **产物之外的上下文**：用户的口头偏好、环境坑、本地依赖状态——产物装不下、但接手的人不知道就会吃亏的。
4. **中断与提醒**：进行到一半的状态（如哪些 task 已全绿）、给下一阶段的具体提醒。

写完随本阶段产物一起提交。

## 读交接

新会话接手 issue 时，先读 `handoff.md` 定位现状，据它决定细读哪些产物、从哪读起。

它只负责导航——本阶段依赖的上游产物（如 build 之于 spec / plan / tasks）该细读的仍然细读。

## 核心原则

- **产物是事实源** —— 交接与产物冲突时以产物为准，发现冲突就修交接。
- **只放指针和增量** —— 决策给指针，事实留在产物里；增量只收产物装不下的上下文。
- **一屏读完** —— 滚动更新、删过时内容，越长导航价值越低。
- **随阶段提交** —— handoff.md 跟着本阶段产物一起进 commit，git 历史就是逐阶段的交接存档。

## 危险信号

- 「把 spec 的要点抄一段过来，接手的人就不用翻了」—— 复述必然漂移，给章节指针，事实只留在产物里。
- 「上次写的还没过时，往后追加一段就行」—— 追加出来的是日志不是导航，整体重写、删掉过时的。
- 「这个坑先记在交接里，产物以后再改」—— 和产物冲突的事实回产物改（或走 **backtrack**），交接只记产物装不下的。
- 「写一句"本阶段完成，进入下一步"就够了」—— 等于没交接：决策指针、中断点、环境坑，接手的人一样都猜不出来。
