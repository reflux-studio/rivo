# 评审产物

审一份产物，判定它能不能放行进入下一步。不管审什么，三样东西不变：逐条列发现、每条给证据和严重度、末尾给放行判定。

## 取评审清单

按产物类型先读对应清单再开审，清单开头列了该备齐的对照材料：

- 需求规格 spec → [checklists/spec.md](checklists/spec.md)
- UI 规格 ui-spec → [checklists/ui-spec.md](checklists/ui-spec.md)
- 技术方案 plan → [checklists/plan.md](checklists/plan.md)
- 代码改动 → [checklists/code.md](checklists/code.md)

没有现成清单的产物，按同样的思路自拟评审项：它对上游的约定守住没有、下游拿它能不能直接干活。

## 内审还是外审

默认内审：你自己按清单审。想要跨厂商的独立视角，或用户习惯用某个外部模型做评审，就做外审：把待审产物、对照材料、评审清单和报告格式写成一份自包含的提示词文件，调本机的外部 AI CLI 在全新上下文里审，怎么调见 [external-audit.md](external-audit.md)。

用不用外审、用哪家模型，按用户的习惯和指定来，拿不准就问一次、记住答案。外审的结论同样按下面的报告格式落盘，标明出自哪个模型；采不采信由你复核，外部模型的话也不是证据，它给的每条发现照样要对得上原文。

## 产出

评审报告按 [review.md](../../templates/review.md) 模板写（rivo 里落到 `.rivo/issues/<id>/reviews/<产物>-<轮次>.md`）：逐条发现给严重度、原文引用或 文件:行号、对照依据；末尾给放行判定。判定不放行，就别把评审任务标完成。

续轮评审先读同目录的历史报告接上，别凭印象。

## 核心原则

- **默认不信**：假定它放行不了，要拿证据证明能放行；找不到问题，往往是没找对地方。
- **凭可复现的证据**：原文、diff、类型检查、测试结果，读得到、对得上的才下判断；跑起来的行为归动态验收，不在这一步。
- **只给结论**：审完写报告，回报给拉起你的人。问题照实标清属性——是实现不符合上游约定，还是上游产物本身有漏洞或歧义——但谁来改、要不要退回上游，不归你管。

## 危险信号

- 「读着挺顺，过」：顺不等于对，逐项拿清单量。
- 「产物自己说覆盖了，那就覆盖了」：自述不算证据，对着来源材料核。
- 「小毛病提了像挑刺」：真问题就提，误报是可接受的成本。
