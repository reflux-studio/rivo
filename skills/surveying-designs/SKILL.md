# 勘测设计体系

从配置和组件代码归纳出这个项目的设计语言，落成文档——之后的界面设计从这里引用 token、匹配组件，而不是每次重新发明。没有前端界面的项目，这份技能不出场。

## 工作流程

### 1. 定位设计的事实源

- 主题与 token 的配置：tailwind 配置、CSS 变量、design tokens 文件、组件库的主题定制入口。
- 组件库依赖：用的哪个库、什么版本、有没有统一的二次封装层（`components/ui` 一类的包装目录）。
- 全局样式与布局骨架。

### 2. 归纳 token

- 颜色、字号与字距、间距、圆角、阴影——**从配置文件读，不从视觉猜**。
- 记 token 名和值；项目自定义的和组件库默认的分开标。

### 3. 盘点组件

- **组件库层**：主力组件库与版本；项目惯用哪些高级组件（表格、表单、筛选类的封装）。
- **业务组件清单**：从组件目录里找长出来的领域组件——订单卡片、客户选择器这类。每个记四样：名字、干什么、住在哪、什么时候该用它。**被两处以上使用的才进清单**，一次性组件不算。
- 这份清单是界面设计做组件选型时三层匹配的第一层数据源，宁可少而准，不要全而杂。

### 4. 断点与布局惯例

- 响应式断点的定义与出处。
- 栅格或布局的既有模式（页面骨架、间距节奏）。

### 5. 落成文档与核验

- 产出 `DESIGN.md`；每个 token 回指配置出处，每个业务组件确认真实存在且有使用处。

## 产出结构

```markdown
# DESIGN

## Token
[颜色 / 字体 / 间距 / 圆角 / 阴影，token 名 + 值 + 配置出处；自定义与库默认分开标]

## 组件库
[库与版本、二次封装层的位置、惯用的高级组件]

## 业务组件清单
| 组件 | 干什么 | 位置 | 什么时候用 |
|------|--------|------|-----------|
| OrderCard | 订单摘要展示 | components/business/OrderCard | 列表与详情页的订单块 |

## 断点与布局
[断点定义 + 出处、布局惯例]

## 待确认
[读不出结论的推断项]
```

## 注意事项

- 勘测记录事实，不做评论——「这套颜色不好看」不属于这份产出。
- 事实源是配置和代码，不是截图；配置里没有的「视觉规律」，标注推断。
- 新旧并存的如实记（「新页面用 token，旧页面还有硬编码色值」），不整理成假象中的统一。
- 文档落成后随代码演进增量更新（复盘时同步），不推倒重跑。
