# ADR 模板

ADR（架构决策记录）保存重要取舍及其理由，供评审和以后修改时查阅。

## 什么时候写

一个决定同时满足两条，就写成 ADR：
1. 做决定时存在不止一个可行选项
2. 推翻它会造成返工，或它约束了其他模块和后续决定

其余决定记进 note.md 的“已确认的做法”，写方案时纳入 plan.md。

## 位置与编号

`.rivo/issues/<slug>/adr/<编号>-<主题>.md`。编号在本需求内从 001 开始，随需求一起归档。

## 模板

```markdown
# <编号>：<一句话写出选了什么>

状态：接受（用户，<日期>）
依赖：<上游 ADR 编号，没有写“无”>
影响模块：<需求总览中的模块 ID>

## 背景

什么场景下要做这个决定，已经查实的限制。

## 可行选项

当时真正可行的几个做法，各自在同一场景下的行为和代价。

## 决定与理由

选了哪个，为什么在当前约束下成立。

## 后果

带来的收益和代价，对其他模块、方案或已有实现的影响。
```

- **状态写真实来源**：用户决定写“接受（用户，日期）”；用户明确委托 AI 选择的写“接受（用户委托 AI，日期）”；事后补写的注明“补记”
- **选项不编造**：只写讨论中真实出现过的选项。约束下只有一个可行做法时，说明原因

## 更新与替换

| 情况 | 处理 |
| --- | --- |
| 决定还没写进获批的方案 | 原位改写成当前的决定，不保留修改痕迹 |
| 方案获批后决定改变 | 新建一份 ADR，在“背景”里写明替换哪一份、依据什么新证据；旧的一份状态改为“已被 00N 替换”，其余不动 |
| 决定不变，只订正措辞或事实 | 原位订正 |
