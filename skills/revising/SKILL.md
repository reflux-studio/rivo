# 修订已确认的内容

开始时说明正在使用 `rivo:revising`，并用一句话说明本次要做什么。同一项工作中不重复声明。

产物之间有上下游：决定约束方案，方案约束实施方案，实施方案约束代码。改动从受影响的最上游一层开始，逐层改到实现，每一层都核对过才算完成。

本技能是交付流程的一部分，只管修订的顺序和完整性。每类产物怎样写，由负责它的技能规定。

## 流程

### 1. 确定从哪一层改起

| 要改变的内容 | 起点 |
| --- | --- |
| 范围、业务行为，或 decisions.md、`adr/` 中的某项决定 | 决定 |
| plan.md 写明的行为、契约或验收，决定不变 | 技术方案 |
| task.md 的任务划分、顺序或共同约定，方案不变 | 实施方案 |

- **往上游查**：方案里要改的内容对应某条决定时，起点是决定
- **缺事实先查**：新证据需要核实时，加载 investigating
- **分清修订和补记**：用户做过决定、只是漏记的，补记后继续，不走修订
- **方案没写到的实现选择不是修订**：由执行者在任务范围内决定，记进 task.md 的实施记录

### 2. 取得用户的决定

向用户说明：

```markdown
原来的约定：<决定的编号、ADR 或 plan.md 的版本与内容>
实际发现：<代码、运行结果、测量数据等证据>
具体后果：<照原约定做，什么场景下会发生什么>
处理建议：<怎样改，以及各选项的代价>
影响范围：<要改的产物、受影响的任务、已完成的工作和协作方>
```

改变决定由用户决定，改变方案由用户确认。沉默不算同意。

### 3. 从起点逐层往下改

| 层 | 产物 | 做法 |
| --- | --- | --- |
| 决定 | decisions.md、`adr/` | 加载 converging 更新，沿依赖检查下游决定 |
| 技术方案 | plan.md、`assets/` | 加载 writing-plans 修订，版本递增 |
| 实施方案 | task.md | 按 implementing-plans 重写受影响的任务，实施记录追加一条 |
| 实现 | 代码、`evidence/` | 受影响的已完成任务按新方案重做或重新验证 |

- **不跳层**：起点以下的每一层都要检查。不需要改的，也确认它与上游一致
- **上游确认后再改下游**：决定定下后再改方案，方案确认后再改任务和代码

### 4. 核对并报告

- 在各层产物中搜索旧的说法，清理残留
- 向用户报告：每一层改了什么，哪些核对过不需要改，哪些任务要重做或重新验证

## 修订期间

- 不依赖改动部分的工作继续进行
- 依赖改动部分的工作，等它的上游确认后再继续
- 原有的批准和实施授权继续有效，除非用户收回
- 修订由用户直接确认，不重新做独立审阅
