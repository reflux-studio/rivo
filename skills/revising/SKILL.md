# 修订已确认的内容

开始时说明正在使用 `rivo:revising`，并用一句话说明本次要改什么。同一项工作中不重复声明。

修改从发生变化的依据开始，沿依赖逐项检查。不同工作有不同的依赖关系：需求规则可能影响方案和用例，研究结论可能影响产品方向，运行证据可能推翻原来的质量判断。本技能负责找到影响范围；各类产物怎样写，仍由相应方法和负责人决定。

## 流程

### 1. 找到修订的起点

读取当前有效材料和原来的确认来源，核对这次真正改变了什么：
- **往依据查**：表面上要改的是一份方案，但它依赖的规则也变了，起点就应当是规则
- **缺事实先查**：加载 `rivo:investigating` 核实新证据，再判断影响
- **分清修订和补记**：已经做过决定、只是漏记的，补记来源后继续，不虚构一次新决定
- **分清约定和局部做法**：没有改变已确认内容的局部选择，由当前负责人在授权范围内处理

列出直接和间接依赖本次变化的材料、已完成工作及参与方。名称和位置以当前任务的实际绑定为准，不新建另一套有效产物。

### 2. 核对决定权与授权

向有权处理的人说明：

```markdown
原来的约定：<来源、版本和内容>
实际发现：<原始资料、运行结果或其他证据>
具体后果：<继续按原约定做，什么场景会发生什么>
处理建议：<怎样改，各选项的代价>
影响范围：<相关产物、已完成工作、需要重验的部分和其他负责人>
```

本人负责且授权覆盖的修改直接处理；他人的产物通过 `rivo:collaborating` 提出请求。用户明确保留的决定等待实际确认，沉默和其他会话转述不能代替。已有授权继续沿用，不因为修订扩大权限。

### 3. 保存可恢复的原内容

改写前逐个核对原内容能否从具体提交或归档恢复。未提交的材料也要可恢复；没有可靠历史时，按当前工作约定保存原内容和来源版本。

快照用于保留历史，不作为第二份当前材料。原运行和失败证据保留原样，新结果另存。

### 4. 按依赖顺序更新

先处理上游依据，再处理依赖它的本人产物：
- **每项都核对**：不需要修改的，也要确认仍与新依据一致，不能直接跳到最终实现
- **保持原位有效**：加载相应写作方法，改写受影响段落，保留约定的版本和修订记录。正文只讲当前做法，读起来像第一次就写对了
- **不追加补丁句**：清理失效的解释、例子和对比。被放弃的选项确实有助于理解时，留在决定理由中
- **尊重其他负责人**：通知变化和影响，由对方更新其产物；引用来源，不复制一份需要同步的契约
- **核对已完成工作**：原先通过的验证是否还覆盖当前版本，需要重做的部分按新依据处理

依赖未定内容的工作等待其上游确认，不依赖的部分继续。

### 5. 核对并报告

在本人材料中搜索旧说法，检查相互引用和版本，按影响重新验证。修订采用当前领域的确认和审阅约定，不自行增加全量重审。

报告哪些已改、哪些核对后无需改、哪些验证需要重做，以及需要其他负责人处理或仍受阻的部分。完成当前修订后回到原任务。
