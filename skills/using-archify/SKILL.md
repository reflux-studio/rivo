# 使用 Archify

让图参与讨论，并与最终文档保持一致。现状图回答“现在如何工作”，目标图回答“这次准备改变什么”。正文保留完整规则，图帮助理解。

开始时声明：“正在使用 rivo:using-archify，绘制并展示当前讨论的系统关系。”随后从技能列表加载原生 archify，按它的 schema、校验和交付要求生成图。Archify 是技能，不是通过工具搜索查找的服务。

**Rivo 使用支持 `deliver --format svg` 的 Archify。直接交付 SVG，不另写 HTML 文档，不从 HTML 临时提取图片。**

## 绘图过程

1. **明确本轮问题。** 决定图要解释哪些对象、关系或行为，以及本期范围。
2. **核实事实。** 现状依据实际调用、配置或运行结果；候选依据讨论中的选择。分开保存现状与目标。
3. **加载 Archify 并编写图源。** 选择匹配的图类型，读取相应 schema，使用稳定的对象 ID。
4. **校验并交付 SVG。** 修复诊断后生成当前图，保留图源与交付回执。
5. **检查并展示。** 查看实际 SVG，确认图文一致、可读，再在当前讨论中展示；听取反馈后更新候选。
6. **留存并交回当前阶段。** 保存能恢复的已确认版本。阶段结论获批、写入 Spec 或 plan 时，再把图嵌入对应段落。

讨论期间只更新图源与 SVG，回到当前问题继续对齐；本技能不授权提前写入或修改 Spec、plan。

文件已生成不等于用户已经看到。用宿主支持的图片展示方式呈现 SVG；无法内嵌时打开实际文件并说明显示限制，不用文件路径冒充展示完成。

## 先画对，再画清楚

现状只画已核实的对象和关系。代码存在不代表已接入，连线必须有调用、配置或运行证据。未能核实的关系明确说明未知；不要添加“计划接入”虚线补满现状图。

沿用知识库中的图源前先核对事实，历史方案不能直接充当 before。用户纠正基线时，说明改变及其影响，保留旧版本，修正相关结论和候选。

从核实后的 before 复制 target，保留相同对象的 ID 和相近布局。分别交付现状与目标 SVG，在会话和正文中依次展示，紧接着说明新增、修改和移除的关系。用户未批准的 target 必须标明候选。

按问题选图：组件协作用架构图，操作顺序用流程图，调用和回调用时序图，状态转换用生命周期图，数据流转用数据流图。每张图解释一个主要问题。复杂内容拆成有明确用途的图，不把完整技术方案塞进一张组件地图。

图中文字采用业务名称，并与正文中的代码标识对应。检查图例是否符合真实含义，不能让渲染器默认标签引入不存在的 Agent 或外部系统。

## 直接交付 SVG

以下命令中的技能根目录和文件路径，使用当前安装与本任务的实际位置。先按原生技能验证 JSON，再执行：

```bash
node <archify-root>/bin/archify.mjs deliver <type> <candidate.json> <output.svg> \
  --format svg --theme auto --quality showcase --json
```

`auto` 随阅读环境切换明暗主题；明确需要固定主题时使用 `light` 或 `dark`。不要把输出扩展名改成 `.svg` 就当作 SVG 交付，必须使用格式参数并检查回执中的 `format`、`theme` 和 `svgValidation`。

非零退出不是成功；输出路径可能仍是上次产物，不能作为本轮结果交付。修复图源后重新校验和交付，不能手改 SVG 使它与 JSON 分离。

交付回执证明自动检查结果，不证明图中事实或视觉质量。打开最终 SVG 或实际渲染图，检查节点文字、连线含义、遮挡、裁切、主题和正文中的阅读尺寸，再分别报告校验与视觉检查结果。原生 `visual-check <output.html>` 不等于支持 SVG；不要对 SVG 套用该命令或宣称它完成了浏览器检查。

## 保存与嵌入

沿用需求目录，默认保存到 `.rivo/issues/<slug>/assets/architecture/`：

- `before.architecture.json` 与 `before.svg`：核实后的现状。
- `target.architecture.json` 与 `target.svg`：讨论中的目标。
- 其他图按用途命名，例如 `approval.sequence.json` 与 `approval.svg`。
- 回执随图保存，需要留存的视觉证据放在本需求的 `evidence/`。

使用明确输出路径，不写入插件安装目录。用户或项目已有位置约定时沿用。用户确认后，用版本控制或快照保留当时的 JSON 和 SVG，不能只记一个无法恢复内容的哈希。

在对应段落直接嵌入图片：

```markdown
审批以模板为单位，每个模板独立接收审批结果。某个模板被退回时，
其他模板已经通过的结果保留，整次活动要等全部模板通过后才能归档。

![各模板独立审批，全部通过后活动归档](assets/architecture/approval.svg)

收到回调后，系统先定位模板主任务，再核对当前流程号与允许的状态。
过期流程的回调不修改新一轮审批结果。
```

这段文字只是排版示例，业务规则以本任务的决定为准。不要复制示例事实。文件内使用能随目录移动的相对图片路径；在会话中按宿主要求展示本地图片。

## 能力缺口

从技能列表和已声明的安装位置核实是否安装。确实未安装时明确说明：“当前环境未安装 Archify，使用 Mermaid 替代。”按实际使用的格式写 ASCII、Mermaid 或 PlantUML，无需另问降级许可。

已经安装却缺少 SVG CLI 能力，或运行失败时，报告实际版本与原因，不能说未安装，也不自行增加 HTML 提取路线。保留已完成的调查和图源，说明图示交付尚未完成；继续不依赖该能力的工作。

## 交付后维护

目标获批不代表已经实现。实施完成后，按实际改动核实图源，再通过 knowledge-management 更新知识库中的现状。先检查知识库是否已被其他任务修改，合并已实现的变化，保留无关内容。需求中的 before 和已确认 target 随需求留存。
