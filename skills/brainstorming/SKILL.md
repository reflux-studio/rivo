# Brainstorming

与用户共同查清问题、作出有依据的选择，把设计打磨到本次请求需要的深度。调研、需求对齐、决策和设计围绕同一个问题交替推进，不要求依次完成独立阶段。

## Checklist

用宿主任务工具建立以下清单，再开始调查；已有清单补齐沿用。无任务工具时在对话中保留短清单。

- 查证现状，确认影响范围和已有能力。
- 与用户对齐目标、范围和行为预期。
- 比较重要做法，形成设计结论。
- 展示关键变化的现状／目标对比。
- 保存已确认的需求、决定和技术方案。
- 核对产物与结论，交付或衔接实施。

按用户要求的深度选用：只调查保留调查与交付；只评审需求不增加技术方案；没有重要取舍无需 ADR。这些是需要完成的工作，不是六个封闭阶段——调查、讨论和图示按问题依赖交替推进。

只有实际完成才勾选。展示项须有已展示的图，保存项须已调用写作技能并完成核对。不适用的项说明原因后移出待办，不伪装成完成。具体问题放子任务，不替换固定清单项。

## 查证事实

承接已有需求、设计稿、知识与决定，找本次变化及影响判断的缺口。沿受影响的用户路径核查入口、状态、调用和结果。准备复用某项能力时，确认它的实际语义、业务差异、依赖和限制，不凭名称判断可行。

区分业务要求、实现行为与待验证推测，结论附来源。能从代码或资料查明的事实由 AI 调查，不把技术事实问题转交用户。证据不足时说明缺口及确认方式。

## 逐步讨论

每轮先呈现已知依据、本次变化和当前需要决定的问题，再给出建议及具体后果。聚焦改变范围、行为、结构、成本或协作承诺的选择。独立且容易的问题可合并。

澄清目标、非目标、角色、可观察行为与验收。涉及页面时明确入口、信息层级、操作位置、状态反馈和异常恢复。术语或规则有歧义时使用 [domain-modeling](../domain-modeling/SKILL.md)。

比较有实质差异的做法，包括现状沿用方案。讲清获得什么、改什么、影响谁、代价与条件。已有决定和委托直接沿用。需要人判断的选择必须展开讨论，不用一次生成文档代替对齐。

## 展开设计

先讲总体做法与主要改动，再按依赖展开模块、组件、数据流、接口和机制。用具体名称说明新增、修改、复用和迁移。

解释契约行为：何时可调用、成功表示什么、数据何时生效、失败和重试如何处理。关键机制展开到可判断保证能否成立；远期部分保留边界和依赖，逐行实现留给编码。不因当前仓库或职责遗漏外部系统。

## 展示变化

讨论流程、状态生命周期、跨模块调用、数据流或职责划分的实质变化时，调用 Archify 呈现现状与目标或候选方案。在用户需要判断的当轮展示，不等方案结束才补图。已有准确的图可复用。

**触发条件**：存在上述关系的实质变化，且用户需要基于此作判断。
**不适用**：用户明确不需要图，或本次不涉及这些变化——说明即可。
**降级**：Archify 不可用时说明原因，用 Mermaid、表格或文字继续，如实记录替代方式，不标成 Archify 已完成。
**UI 形态**结合设计稿或原型，不由 Archify 处理。

## 保存结论

按实际需要调用 [writing-docs](../writing-docs/SKILL.md)，传入结论、来源、确认依据、未决项和目标位置。

| 需要保存什么 | 模板 |
| --- | --- |
| 需求、行为、UI 形态与验收约定 | Spec |
| 值得长期解释的重要决定与取舍 | ADR |
| 足以供团队评审的完整技术方案 | 技术方案 |

及时保留重要决定的理由，不等完整方案结束。常规选择留在技术方案中。草稿可随讨论保存。写作技能交回后继续当前问题，不因写完文件重启讨论。

新证据与已确认结论碰撞时，说明原约定、发现、后果和建议。需要改变重要决定时在既有委托内处理；未获决定暂停依赖部分。通过 writing-docs 更新受影响材料。

## 合理化预防

| 想法 | 实际 |
| --- | --- |
| "先写完方案再补图" | 图示随讨论出现，不等方案结束 |
| "这个不需要讨论，直接写" | 需要人判断的选择必须展开讨论 |
| "模板太重，不用读了" | 写作技能负责读模板，不跳过 |
| "用户没提，不需要查" | 影响判断的事实由 AI 主动调查 |
| "调查清单太长了，先做能做的" | 具体问题放子任务，不替换展示和保存项 |

## 后续衔接

完成用户要求的深度后，核对清单的展示、保存和确认结果，交付结论与未决项。方案可实施且有授权时使用 [incremental-delivery](../incremental-delivery/SKILL.md)；只要求评审或方案时不进入实施。知识维护使用 [knowledge-management](../knowledge-management/SKILL.md)。
