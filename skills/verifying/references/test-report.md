# 验证报告模板

在改动交付、整体验收或团队归档前汇总实测事实。好消息和坏消息都要写：跑过什么、在什么条件下跑的、哪里没能覆盖。团队有自己的报告模板时用团队的。

```markdown
# <需求或改动名称>：验证报告

| 项目 | 内容 |
| --- | --- |
| 验证结论 | 通过／有条件通过／不通过（一句话给出上线/验收建议） |
| 代码版本 | <各仓库路径、分支与当前 commit / diff 基线> |
| 依据 | <需求或 PRD、技术方案版本、测试方案版本（如有）> |
| 验证环境 | <本地 / 测试环境 / 预发环境；外部平台执行链接（如有）> |

## 分层验证汇总

| 层级 | 执行范围与命令 | 通过 / 失败 / 跳过 | 运行条件（含 Mock 说明） | 证据索引 |
| --- | --- | --- | --- | --- |
| 静态检查 | <typecheck / build / lint> | — | 真实工程 | <路径或输出摘要> |
| 单元测试 | <测试套件范围> | — | <无 mock / mock 范围> | <路径> |
| 集成测试 | <接口与跨仓契约范围> | — | <测试 DB / 真实上游> | <路径或平台链接> |
| 端到端与页面实测 | <跨模块主干、P0 冒烟、影响面路径> | — | <浏览器/测试环境> | <截图或视频路径> |
| 人工验收 | <关键交互或阶段验收结论> | — | <确认人或待确认项> | <记录位置> |

## 用例与回归核对

- **测试方案执行**：共 <N> 条（P0 <x> / P1 <y> / P2 <z>），已通过 <m> 条；实施中按代码细节补充用例 <k> 条
- **老功能影响面回归**：<列明受影响老功能的实测结果，是否均保持正常>
- **未通过或跳过条目**：<编号、原因及后续处理计划；全部通过则写“无”>

## 阻塞缺陷与复测记录

| 编号 | 问题描述 | 引入 / 发现节点 | 修复说明 | 复测范围与结果 |
| --- | --- | --- | --- | --- |
| — | 无阻塞缺陷 | — | — | — |

## 未覆盖范围与遗留风险

- **受限未覆盖**：<例如未开通第三方沙箱、真机 iOS 未测、生产历史大表仅抽取样条验证等>
- **遗留问题**：<未修的 P1 / P2 事项、已知限制与影响评估>
```
