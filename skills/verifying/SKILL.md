# 分层验证与回归测试

用最短的反馈路径证实改动真实可用，如实区分“已经运行并证明”和“尚未覆盖”的范围，不用口头猜测或全 mock 测试代替集成验证。

## 1. 按从快到慢的顺序验证

越便宜、越快、越自动化的检查放越前面；前一层的阻塞问题没通过，不浪费时间和人力跑到后面：

1. **静态检查**：编译、类型检查、Lint、生成的协议或类型文件同步
2. **单元测试**：纯逻辑、等价类、边界值与状态分支
3. **集成与契约测试**：模块拼接、数据库事务、权限拦截、跨服务与跨仓库真实调用
4. **端到端测试与人工验收**：核心主干链路、真实页面渲染与交互体验

## 2. 分层回归策略

避免每改一行就全量重跑慢速测试，也避免后续改动悄悄破坏已有功能：

- **自动测试全量跑（合入或验收前）**：完整运行静态检查、全量单元测试和全量集成测试。机器自动跑几乎不占上下文开销，专门用来发现“后面的改动把前面改坏了”
- **端到端与人工测试按影响面跑**：端到端测试、真机页面实测与外部平台回归，不把细碎参数边界再走一遍，只跑三类路径：
  1. 跨模块串联的核心主干链路
  2. 全部 `P0` 核心冒烟场景
  3. 本次改动及公共依赖波及的老功能回归范围
- **局部修改后的定向复测**：人工验收、代码审阅或最终验证触发修改后，按影响面定向复测——纯样式或文案微调只复验受影响页面与构建；改动业务逻辑时，先补充或更新对应自动测试，再重跑受影响的检查，不整套推倒重来
- **对接外部测试平台**：如果项目约定通过 MeterSphere、Etest 等平台执行接口或回归测试，在授权范围内按项目规范（如 `AGENTS.md`）触发或导出同步，并保留平台报告链接与实测结论

## 3. 真实证据纪律

- **没有基于当前最新代码实际跑过并看到完整结果，不得宣称“通过”**：历史成功结果在代码再次修改后自动作废
- **如实标注运行条件**：写清每次运行使用的是全 mock、内存替身、测试环境还是真实联调环境，不得用全 mock 冒充集成已打通
- **留证并清理临时文件**：截图、命令日志与回归输出放入指定的证据目录；排查时写的临时脚本或测试脏数据用完即删，不留在源码仓库

## 4. 产出独立验证报告

面向验收、合入前检查或团队归档时，按 [独立验证报告模板](references/test-report.md) 产出 `test-report.md`（写入调用方或项目指定的位置），把各层统计、用例与回归核对、缺陷复测、证据索引和**未覆盖范围**一次说清。
