# 维护项目知识

开始时说明正在使用 `rivo:knowledge-management`，并用一句话说明本次要做什么。同一项工作中不重复声明。

知识库只写已经实现并核实的现状，解释机制、约束和理由。

## 收尾流程

### 1. 确认验收

- 根据完整上下文判断用户是否已经验收，不要求固定措辞
- 已有验收直接沿用；尚未明确时再询问
- 验收前保留需求材料，不更新知识库，也不归档

### 2. 核实本次变化

- **找到知识库**：用户或项目指定的位置优先，其次沿用已有知识库，没有时用 `.rivo/knowledge/`
- **读本次材料**：需求总览、ADR、调查结论、plan.md、task.md 的实施记录和图
- **对照实际**：用最新代码或运行结果核实结论。尚未实现或无法核实的内容不写成现状
- **保留别人的更新**：比较 note.md 记下的知识库初始版本与当前版本，其他工作写入的内容保持原样

### 3. 写入知识库

- **结构**：按 [知识文档结构](references/knowledge.md)，项目已有模板和主题划分优先
- **表达**：加载 writing-clearly
- **在原主题重写**：已有主题改写受影响的段落；只有独立的新主题才新建文件
- **补导读**：在首页补上新主题的导读和链接

知识库的其余部分保持原样。

### 4. 归档

1. 把整个需求目录移入 `.rivo/archived/<slug>/`，包括 ADR、审阅报告、证据和图
2. 修复指向旧位置的链接，核实目标存在

仍有影响知识正确性的未决事项时，保留原目录并说明待收尾的范围；用户同意不阻塞后再归档。

### 5. 向用户报告

- 改写或新增了哪些主题
- 目录归档到哪里，修复了哪些链接
- 仍未核实或需要用户决定的事项

## 单独调用

单独调用不需要验收，也不自动归档。

| 请求 | 做法 |
| --- | --- |
| 查阅项目知识 | 从首页找到相关主题，回答并给出来源。结论会影响接下来的工作时对照代码核实，不符的地方告诉用户 |
| 整理单独调查的笔记 | 按收尾流程第 2、3 步写入。调查目录是否归档由用户决定 |
| 重写已有知识 | 按用户给的范围改写。原有内容逐条对照代码核实，不符的列给用户决定 |

发现知识与代码不符时分清原因：知识过时就订正；代码偏离了用户的决定就交回原任务；证据不足就标明待核实。
