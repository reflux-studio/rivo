# 知识的组织与维护

选定知识根目录后再使用以下结构；调用方可提供任何位置。Rivo 的默认位置由 using-rivo 管理。

## 按内容增长

```text
<知识根目录>/
├── README.md                 # 知识导航，小项目也可直接保存内容
├── <业务或产品主题>/
│   ├── README.md             # 主题现状概览
│   ├── glossary.md           # 名词解释，内容需要时再拆
│   └── workflows.md          # 流程或交互约定，按需
└── <应用或工程主题>/
    └── README.md             # 系统结构、工程约定、限制与相关入口
```

不生成空目录，也不要求固定领域分层。先有可读内容，再按读者要解决的问题拆分；一个术语或决定不在多份文档独立维护。

导航说明每个主题包含什么、什么时候读、入口在哪里。主题概览可以包含适用范围、当前结构或流程、关键规则、重要决定和已知限制，按主题选择即可。

## 结论的依据

```markdown
结论与适用范围：
性质：业务约定／实现事实／待验证推断
理由、解释它的场景或反例：
来源：原始资料、ADR、相关代码或验证证据
版本或最近核实时间（影响时效时）：
```

无需为每句话重复元数据；同一段共用来源即可。名词解释聚焦含义和区别；详细方案、任务流水与测试原稿留在交付材料中，知识文档链接必要依据。

## 替代与清理

1. 核实旧结论因何失效，以及是否仍适用于其他版本或范围。
2. 更新当前说明，保留旧理由与替代来源；无可靠历史记录时先归档有价值的旧内容。
3. 修复受影响导航、交叉引用和源材料链接。交付目录移动到归档后重新指向有效位置。

把“已决定采用”与“已经实施并验证”分别表达。例如通过审批的目标流程尚未实现时，不将它替换成现状流程。

项目已有 wiki、工程文档或知识索引时，映射这些信息即可，不建立竞争的副本。大量迁移按当前任务范围进行，不因为使用了本技能就重组整个知识库。
