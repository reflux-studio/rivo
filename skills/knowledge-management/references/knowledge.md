# 知识文档结构

优先沿用项目已有模板、主题划分和导航。新主题按读者用途选择结构，首页只导航到能独立理解的主题。文件长度不决定是否拆分。

## 机制说明

```markdown
# <机制或能力>

适用范围：<系统、版本与环境>

## 概览
<能力、使用场景及系统中的位置>

## 工作方式
<入口、数据或状态流转、参与组件；按机制展开子章节>

## 约束与设计理由
<调用或修改时需遵守的契约、边界及重要取舍>

## 使用与维护
<使用方式、修改影响、验证方法与常见故障定位>

## 来源
<来源需求、有效决定与核实证据>
```

## 操作指南与契约参考

| 文档类型 | 默认结构 |
| --- | --- |
| 操作指南 | 适用场景 → 前置条件 → 操作步骤 → 结果检查 → 失败处理 |
| 契约参考 | 用途与适用版本 → 精确定义 → 示例 → 兼容与限制 |

一个主题按它的类型选一种结构，团队已有格式优先。

## 写入时

- **只写已核实的现状**：未知的部分标明范围
- **来源可核实**：指向需求和证据的实际位置，归档后用归档位置。正文仍要把机制讲清楚
- **旧规则注明边界**：仍适用于旧版本的规则保留，并写明适用范围
- **排查经过留在需求记录里**
