# 领域全景与知识模板

## 领域全景文档

每个业务域维护一份全景文档，默认位于 `.rivo/models/<domain>/README.md`。新人读完就能理解这个域的当前状态。按问题删减章节，不要求每次输出完整文档。

```markdown
# <业务域名称>

范围、核心参与者、最后更新与来源：

## 核心概念

参与者、业务对象及其身份、生命周期和责任归属。
（配合流程图、状态图、数据关系图等可视化表达）

## 关键规则

始终必须成立的约束及业务理由：
规则之间的优先级和冲突处理：
哪些是业务约定，哪些是实现事实，哪些是推断：

## 主要流程

正常过程与关键分支：
（配合流程图或时序图）

## 重要决定

仍然有效的架构和业务决定、理由及重新考虑的条件：

## 适用边界

模型尚不能解释的问题：
已知的技术债务或待验证假设：
```

维护原则：

- 过时的内容直接删除——历史在 git 和交付归档里
- 每条重要结论注明来源交付或决定，保留可追溯性
- 图文并茂：复杂关系用图，关键规则用文字
- 宿主或已安装技能提供图表能力时使用它；否则使用 Mermaid 或结构化文字

## 单条知识更新

当知识不属于某个域全景（如跨域知识、排查方法），或全景文档尚不存在时，使用以下结构更新相应载体：

```markdown
## <规则／机制／决定理由>

结论与适用范围：
性质：业务约定／实现事实／待验证推断
解释它的场景与反例：
来源交付、相关决定与验证证据：
```

优先合并进已有文档的对应章节，而不是新建独立文件。
