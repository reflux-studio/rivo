# 任务简报

用于提供当前任务的完整局部上下文，可放在已有任务系统中。按任务填写，删除不适用项，不要求每项交付都存在独立 Spec、ADR 或模型文档。

```markdown
# <编号>：<可验证的能力>

## 目标与范围
用户或调用方可观察的结果：
负责的模块、仓库与可写范围：
相关项目约定与已有授权：

## 当前依据
需求／Spec、ADR、技术方案及相关知识的章节与版本：
必须成立的行为、接口语义与约束：
尚未决定的问题及影响：
当前适用的实施、测试方法的位置或正文：

## 依赖与验收
依赖的接口与行为是否可实际使用：
验收场景、输入、预期结果和验证方式：
值得向用户展示的变化或关键机制：

## 工作区与交接
代码起点、已有未提交改动和其他在途工作：
执行者角色：只完成本任务，不派发子代理：
本轮结果、报告与证据的返回方式：
```

不要只写“参考之前讨论”。提供精确约束和可核对来源，来源不可达时提供必要正文并注明限制。

契约和代码基线用可识别的修订、提交或内容快照固定；可变路径和修改时间不足以固定版本。包含未提交、未跟踪文件时，保留前后快照或等效差异，多仓库分别记录。无需为了审阅而提交代码。
