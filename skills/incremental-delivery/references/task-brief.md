# 任务简报

派发前按需填写，用于提供当前任务的完整局部上下文。已有任务系统可保存同等信息时复用，不要求独立文件或固定字段解析。占位内容应替换为真实信息，不适用项删去。

```markdown
# <任务编号>：<可验证的能力>

## 目标与范围
用户可观察的结果：
本任务负责的模块／仓库／路径：
不包含的邻接工作与其他任务归属：

## 当前依据
相关模型、架构决定、技术方案的来源、章节与版本：
必须成立的具体规则、接口语义和约束：
相关项目约定与授权边界：
已确认的决定、尚未决定的问题：

## 依赖与验收
上游已完成的接口与行为，能否真实使用：
用于判断完成的场景、输入、预期结果：
重要边界／失败情形与验证方式：
需要向用户展示的机制或取舍：

## 执行上下文
角色：仅执行本任务；不再派发子代理。
实施与测试方法的位置或正文：
工作目录、代码基线及已有未提交改动：
可写范围、共享区域和其他在途工作：
执行报告／自审／验证证据的返回位置或方式：
```

必须把与任务有关的精确约束写清楚，同时保留原始来源供核对；不能只给“参考之前讨论”。来源可达时只携带相关章节与必要上下文，不让代理通读整个历史库。来源不可达时提供必要原文并注明限制。

版本可以是不可变修订、提交号或内容快照。文件路径与修改时间不足以固定正在变化的契约。当前范围包含未提交或未跟踪文件时，应有前后快照或等效可复现的差异，不能用 HEAD..HEAD 漏掉它们；多仓库分别记录。工作流不要求为了审阅而提交代码。
