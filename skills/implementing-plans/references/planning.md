# 写 task.md

task.md 是粗粒度的实施方案：交付什么、按什么顺序、守住哪些契约、怎样算完成。怎样实现由执行者读方案和代码后决定。写到逐文件、逐步编码，信息量就等于代码。

## 拆分方法

- **按结果拆**：每项任务交付一项能单独检查的结果，写清用户或调用方能观察到什么
- **不单列配套工作**：配置、脚手架和测试归入需要它们的任务
- **风险先行**：先排影响后续结构的任务，让风险最高的假设最早被验证
- **标明依赖**：没有依赖、也不改同一处的任务可以并行
- **共同约定集中写**：接口名、字段、状态语义、代码风格、工作分支，用 plan.md 中的实际值。单项任务只写特有契约
- **验收可检查**：写场景和预期结果，或指向 plan.md 的验证安排

拆分时发现 plan.md 缺契约，按实施技能的偏离分流，不在 task.md 里补定。

## 结构

```markdown
# <需求名称>：实施方案

依据：plan.md <版本>，adr/<编号范围>。代码仓库、分支与已有授权。

## 共同约定

所有任务都要遵守的契约和工程约定。

## 任务

| 任务 | 可验证结果 | 依赖 |
| --- | --- | --- |
| T1 <名称> | <做完后能观察到什么，必须遵守的特有契约> | 无 |

## 验收

逐任务审阅、整体审阅，以及 plan.md 中要求的验证步骤。

## 实施记录

按任务记录实现选择、被拒绝的非阻塞意见、分级异议和偏离处理。
```

## 自查

- 逐节对照 plan.md，每项需求、契约和验证安排都落在某项任务或共同约定里
- 任务之间没有矛盾的契约

覆盖完整即开工。
