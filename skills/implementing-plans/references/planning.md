# 任务安排

task.md 是执行记录，不是第二份技术方案。任务按可验收结果拆分，执行者自己读设计和代码确定局部实现。脚手架、配置和测试属于需要它们的任务，不为每个活动另建一个阶段。

先安排会验证重要假设的任务。写清任务的可观察结果、依赖、修改边界和必要验证；只有限定范围确有作用时才列文件，不预写逐文件教程。共同约定以当前 plan 的定义为准，任务不复制整份字段与接口表。

文件应能回答：

- 基于哪份已批准的设计和哪些原始范围依据，当前代码与授权是什么。
- 每项任务交付什么、依赖什么、怎样证明完成。
- 哪些任务未开始、在做、待验证、待审或已完成。
- 实际验证结果、证据位置、实现选择、保留问题和方案变化。

这些信息可用简短表格与记录表达，不要求固定目录。发现设计缺口时先处理事实或决定，不在 task 中偷偷补定共同契约。

方案修订时，标明哪些任务仍在原批准范围内，哪些等待新决定；结论确定后在原处更新任务和验收要求。记录中的完成结论绑定实际方案与代码版本，不能靠修改旧任务文字把先前证据自动当成新验证。
