# Write Design

将已有设计结论整理为可供团队评审的文档。接收设计材料、来源、确认依据、Spec/ADR 引用、图源版本、未决项与位置；可以独立使用，不要求先运行阶段流程。

## 写作与核对

1. 新建或实质修订前读取 [技术方案模板](references/system-design.md) 和已有目标文档。
2. 按模板先说明总体做法与主要变化，再按实际模块组织改动、复用依据、数据流、接口和关键机制，补齐已有材料中的影响与验证安排。
3. 对照模板核对元信息、七个主章节和适用字段，核对实际对象、契约、图源与结论一致，检查依赖与未决项是否保持可见。
4. 交回位置、主要变化及未决项。被调用时继续原问题；独立写作完成后结束。

保留模板主结构，细节按实际范围裁剪；用户指定其他格式时按其要求。被调用时嵌入当前清单项，不另建竞争清单。

## 内容边界

需求引用 Spec 或权威 PRD，重要取舍引用 ADR，接口以权威契约为准。不因执行职责或当前仓库遗漏外部依赖。复杂模块可拆附属文档，主方案保留总体流程和验证安排。

引用已经形成的 compare 阅读入口、before/target 图源及确认版本，不用补画图替代尚未完成的设计讨论。事实或决定缺失时明确标注，不编造契约、保证或确认记录；需要形成设计时交回调用方，独立请求可加载 [technical-design](../technical-design/SKILL.md) 处理具体缺口。

区分提议、已确认方案和已实现状态。任务拆分与派发由 incremental-delivery 负责，写完文档不自动进入实施。
