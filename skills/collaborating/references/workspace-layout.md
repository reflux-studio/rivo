# 默认工作区布局

协作配置未指定后端的产物，一律落在项目仓库的 `.rivo/` 目录。大写文件是跨交付的长期资产，小写目录是单次交付。单次交付中的 requirement、ui-design、system-design 和实现是可被下游依赖的决定或交接节点；其余文件记录状态、过程和证据，不因拥有独立文件名而成为新的决定层。

```text
.rivo/
├── PRODUCT.md          # 产品认知，Product 持有
├── DESIGN.md           # 设计认知，Designer 持有
├── ENGINEERING.md      # 工程认知，Engineer 持有
├── VERIFICATION.md     # 可选；出现项目特有的验证校准知识时由 Verifier 创建
├── PROFILE.md          # 协作配置，全员共同约定，经 onboarding 建立和调整
├── issues/<slug>/      # 进行中的交付
│   ├── state.md            # 当前状态、下一步、产物位置和未关闭发现
│   ├── requirement.md      # 按需
│   ├── ui-design.md        # 按需
│   ├── system-design.md    # 按需
│   ├── implementation.md   # 实现位置、版本、改动摘要、自测和验证入口
│   ├── reviews.md          # 领域交叉评审、作者回应、跳过理由和用户裁决
│   ├── verification.md     # 各版本的独立验证结论和执行证据
│   ├── investigation.md    # 异常排查过程记录；发生调查时创建，不是决定层
│   ├── uat.md              # 有用户可感知结果时创建
│   ├── release.md          # 发布审批、执行、冒烟、监控和回滚记录
│   ├── retro.md            # 值得复盘时创建
│   └── evidence/           # 截图、录屏、日志等无法内嵌的证据，按需创建
└── archived/<slug>/    # 交付完结后整个 issue 目录移入
```

- 协作配置为某类产物指定了外部系统（如 requirement 在工单系统）时，以外部系统为准，`.rivo` 不放副本——一份产物只有一个事实源。
- 未发生的阶段不创建占位文件；同一种记录可以在一个文件中追加多轮，不要求一轮一个文件。
- `state.md` 只保存当前投影，详细过程留在对应记录；配置外部后端时，状态中保留可直接读取事实源的路径或链接。
- `.rivo` 随仓库提交。评审和验证需要区分版本时，使用当前后端能够提供的 commit、文档版本或其他可核对标记，不另建统一版本系统。
- issue 移入 `archived/` 后内部引用使用相对路径，避免归档移动破坏链接。
- `<slug>` 用 3–5 个词的 kebab-case 概括这次交付。

## 默认记录的最小内容

文件名只是默认载体，语义不能缺：

| 记录 | 至少包含 |
| --- | --- |
| `state.md` | 原始请求、入口、当前状态、下一步、产物与记录位置、当前版本、未关闭发现、待响应通知、用户决定 |
| `implementation.md` | 对应方案或目标、源码位置与版本、改动摘要、自动化测试、自测结果、独立验证入口、范围外发现 |
| `reviews.md` | 被评审对象与版本、评审者及领域视角、发现、作者回应、复核结果、跳过理由、用户裁决 |
| `verification.md` | 被验证对象与版本、独立性等级、依据、结论、发现、执行环境与证据、可靠部分、可选建议 |
| `investigation.md` | 预期与实际、复现、证据、根因、被验证或推翻的假设、修复与防回归 |
| `uat.md` | 需求与实现版本、环境和参与人、真实场景、用户操作与原话、发现、结论、可选建议 |
| `release.md` | 目标版本与环境、批准、发布步骤、迁移、冒烟、监控、回滚条件和实际状态 |
| `retro.md` | 有证据的经验、改变走向的事件、下次具体动作、更新的长期认知 |

截图、录屏、日志或实验产物放进 `evidence/`，并从相应记录直接引用。
