# 协作处理问题

工单帮助找到人和材料，问题详情另存记录。各方只修改本人产物，沟通不等于取得对方的决定权。

## 流程

### 1. 找到对应负责人

读取公共 `rivo:using-rivo` 的共享工作区约定和当前工单，核对：
- 本人角色和要处理的问题
- 谁负责相关产物，以及实际位置和版本
- 对方的联系入口和已有授权

角色缺席、联系人重名或来源冲突时，先协调明确。不能猜联系人、自动创建会话或接管工作。每次只读与本次问题有关的记录，不通读全部审计历史。

### 2. 留下具体请求

按 [请求记录](references/request.md) 说明事实、影响、依据版本和希望对方处理什么。缺陷已有正式记录时引用它，不再维护第二份正文。

请求 ID 使用时间、发起方和短后缀，不依赖多人共同递增的计数。原始证据按当前约定保存或引用，精简工单只增加发起索引，问题、回复和处理状态留在详情中。

### 3. 登记发起索引

多人可能同时登记，先核对当前材料支持怎样安全写入：
- **本地文件**：支持原子追加时，用 [登记脚本](scripts/append-request.py) 单次追加完整行
- **在线文档**：使用来源实际支持的条件更新，避免覆盖其他人的新内容
- **不能确认安全写入**：由明确维护者串行登记；没有维护者时保留详情并报告待登记，不覆盖整份工单或建立锁服务

### 4. 转交并记录真实结果

使用实际可用且用户授权的 Agent 通信，发送记录 ID、链接和所需反馈。发送前核对对方是否能读取材料：
- 来源可读时直接引用
- 来源不可读但授权允许时，提供带版本和范围的最小必要摘录；摘录只是这次请求的快照
- 缺少安全传递方式时，保留访问阻塞和解除条件，不自行上传材料或扩大共享权限

向真实同事发送 IM、邮件等外部消息，需要相应授权；允许 Agent 互相联系不包含这类授权。工具缺席或联系人不可达时，留出可由用户转交的记录，继续不依赖回复的工作。

记录实际送达、材料可读和回复情况。送达回执只能说明消息发送结果，不能说明对方已读懂或问题已解决。重发前检查已有回复与交接结果，避免重复通知。

### 5. 回复并接续

接收方读请求和相关依据，只处理本人负责的内容，追加带时间、身份和产物版本的回复。不能修改他人原文，也不能代替对方确认。

发起方对照回复和负责人当前有效产物，核实问题是否已经解决，再继续本人工作。尚有缺口时留在原记录中；具体决定以对应负责人的有效产物为准。

共享目录和默认位置只由 `rivo:using-rivo` 维护。请求详情保留协作往返，不复制另一套需求或项目状态。
