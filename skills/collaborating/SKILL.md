# 协作处理问题

工单帮助找到人和材料，具体问题另存记录。各方只修改本人产物；沟通不等于取得对方的决定权。

## 流程

1. 读公共 using-rivo 的共享工作区约定和当前工单，确认本人角色、接收方、联系入口、产物位置与授权。角色缺席、多人无法判定或来源冲突时先协调，不猜联系人、自动建会话或接管。
2. 按 [请求记录](references/request.md) 保存问题或缺陷、依据版本及期望反馈。请求ID使用时间、发起方与短后缀，避免依赖共享自增计数。原始证据另存或引用，工单只新增发起索引。
3. 安全登记索引：本地支持原子追加时可用 [登记脚本](scripts/append-request.py) 单次追加完整行；在线文档使用实际支持的条件更新。不能确认安全写入时由明确维护者串行登记；无维护者则保留详情并报告待登记，不覆盖整份工单或建立锁服务。
4. 使用实际可用且用户授权的Agent通信，发送记录ID、链接及所需反馈。先核对对方能否读取来源；不可读时仅在已有授权内提供带版本的最小摘录，否则报告访问阻塞。真实同事的IM/邮件等外部消息仍需相应授权，不自动上传材料或扩大共享权限。
5. 接收方读取请求和相关来源，只处理本人产物，追加署名回复及版本引用；不改他人原文或代替他人确认。发起方核对回复后继续本人工作，尚未解决时保留缺口，不把送达回执当作问题已处理。

工具缺席或联系人不可达时，留出可转交的记录和解除条件，继续不依赖反馈的工作。重发前检查已有回复和交接结果，避免重复通知。每次只读相关记录，不通读所有审计历史。

共享目录和默认产物位置只在 using-rivo 维护；请求详情不复制一套需求或项目状态。
