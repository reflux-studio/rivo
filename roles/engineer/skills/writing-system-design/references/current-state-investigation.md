# 现状调查

## 建立地图

- README、依赖、构建和部署配置；
- 目录结构和主要入口；
- 工程认知与最近相关 ADR；
- 受影响模块的测试和监控。

## 跟踪路径

从实际入口沿调用关系向下：

1. 用户、API、任务或事件从哪里进入；
2. 经过哪些模块和边界；
3. 状态在哪里读取和写入；
4. 错误如何传播；
5. 最终结果在哪里被观察。

对关键路径至少走通一条真实调用或测试，不只凭文件名推断。

## 核对架构断言

每个影响方案的断言应回答：

- 证据在哪；
- 当前是否仍然成立；
- 是否只对某些环境或数据成立；
- 错误时会推翻方案的哪一部分。

## 调查历史

需要时查看：

- 最近触碰相关代码的提交；
- 过去事故和缺陷；
- 曾被放弃的方案及原因；
- 依赖升级或配置变化。

历史用于解释现状，不用于机械复刻旧决定。

## 停止条件

已经能回答以下问题时停止继续浏览：

- 改动从哪里进入；
- 哪些模块和数据受影响；
- 现有模式如何解决相似问题；
- 最大风险和未知项是什么；
- 哪些事实足以比较候选方案。

不要为了“全面了解代码库”无限调查。
