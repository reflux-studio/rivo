# 巡查体验与设计系统

巡查记录事实、稳定惯例和无法确认的问题，不借机提出无关改造。深度取决于用途：首次入场覆盖设计系统的核心地图；周期巡视对照已有认知只检查变化——退化、漂移和新出现的可复用模式；专项巡查围绕指定页面或流程深入。已经能支持后续工作时停止。

## 1. 定位事实源

- 设计文件和组件库；
- 主题、token 和全局样式配置；
- 前端组件和业务组件；
- 页面骨架、布局和响应式断点；
- 运行中的主要界面；
- 历史复盘记录（默认在 `.rivo/archived/*/retro.md`）。

优先读取当前真实来源；已有总结只能作为线索，与事实冲突时以可验证来源为准并记录冲突。

## 2. 调研内容

- 颜色、字体、间距、圆角、阴影等 token；
- 主力组件库、版本和二次封装层；
- 被多个场景复用的业务组件；
- 重复出现但尚未进入设计系统的组件和模式；
- 表单、表格、筛选、导航和反馈模式；
- 响应式和设备差异；
- 无障碍和交互惯例；
- 新旧设计并存的边界。

## 3. 核验

- token 从真实配置或设计变量读取，截图只能提供线索；
- 组件确认真实存在，并指出使用位置；
- 一处写法不算惯例，至少找到多个一致实例；
- 设计文件和代码冲突时同时记录，谁覆盖谁交给负责人裁决。

每个重要结论能指出来源；读不出的内容标为推断或待确认。

## 4. 发布

输出设计事实源索引、token 和主题、组件库与业务组件、布局断点和交互模式、无障碍惯例、迁移中或不一致区域、建议收编进设计系统的组件和模式提案，以及推断与待确认项。

按 `collaborating` 的产物发布约定发布；来源由外部团队维护时提出修改建议。收编提案是否采纳由设计认知负责人决定。
