# 设计来源处理

## 可编辑设计源

1. 读取当前修订和图层、组件结构；
2. 标出本次 requirement 对应区域；
3. 先改结构和状态，再处理视觉细节；
4. 更新设计源；
5. 记录修改摘要和仍未解决的问题；
6. 重新检查所有受影响状态，而不只看改动的画板。

## 只读设计源

评论或修改要求必须包含：

- 具体画板、区域、组件或状态；
- 当前问题；
- 对 requirement 或用户任务的影响；
- 期望修改后的行为；
- 是否构成当前版本必须处理的发现。

避免“这里不好看”“优化一下交互”这种无法执行的反馈。

## 外部 AI 设计平台

把反馈转换为适合外部平台执行的指令：

```text
保留：[不应改变的结构和风格]
修改：[具体区域和行为]
新增：[缺失状态或页面]
约束：[组件、token、断点和业务规则]
不要：[容易被模型误改的内容]
验收：[新版本必须能观察到什么]
```

外部平台返回新版本后：

- 确认它没有破坏原本正确的部分；
- 逐条核对修改要求；
- 检查新变化是否引入额外状态缺口；
- 继续修改，直到可以发布 ui-design。

## 截图或无法读取结构的设计

- 明确哪些结论来自视觉观察，哪些无法确认；
- 不从截图猜 token 名、组件参数或真实响应式行为；
- 需要精确施工时，请求设计源、标注或运行界面；
- 暂时无法获得时，把推断和实现自由度写清楚。
