# 验证方法选择

## 审阅与事实核对

适合确认：

- 文档是否自洽；
- 需求、设计和技术方案是否互相对应；
- 代码和配置中的现状断言是否真实；
- 风险、影响面和边界是否完整。

## 构建与自动化测试

适合确认：

- 当前修订可以安装、生成和构建；
- 单元、集成和端到端测试实际通过；
- 静态检查和类型约束成立；
- 已确认问题有稳定防回归证据。

记录完整命令、环境、退出状态和关键输出。

## UI 走查

对照 ui-design 检查：

- 页面结构、组件和文案；
- 默认、加载、空态、错误、权限和成功状态；
- 断点、窄屏和超长内容；
- 鼠标、键盘、焦点和触屏行为；
- 实际操作路径和反馈。

能量化的偏差记录尺寸、截图或 DOM/CSS 证据；主观设计判断交给 Designer。

## 隔离技术试验

当 system-design 依赖尚未证实的技术能力时使用，例如：

- 第三方 API 是否支持关键行为；
- 某库能否满足性能或兼容要求；
- 数据迁移方案是否可行；
- 新协议、格式或运行时是否能与现有系统集成。

规则：

- 在隔离目录、分支或临时环境执行；
- 只验证一个明确假设；
- 先写成功和失败判据；
- 记录代码、命令、数据和结果；
- 不把技术试验当成生产实现继续扩建；
- 结论返回 Engineer，由其决定正式方案。

## 性能、迁移和恢复实验

记录基线、样本量、机器、环境、统计方式和限制。迁移验证同时检查迁入、校验和回退；恢复验证检查服务和数据是否真正回到可用状态。
