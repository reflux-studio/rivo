# 实现验证检查表

## 符合度与范围

- 实现是否对应当前技术方案和验收依据？
- 是否存在未说明的方案偏离？
- 是否夹带无关重构、格式化或功能扩张？
- 每条目标是否有对应实现和自动化测试？

## 构建与静态检查

- 依赖安装、生成步骤和构建是否成功？
- 类型检查、lint、格式或安全扫描是否通过？
- 结果是否来自当前修订和正确环境？

## 正确性

- 空值、空集合、边界数字、超长输入和异常顺序是否正确？
- 错误是否被吞掉、错误类型是否被错误转换？
- 并发、事务、重试和幂等是否适用且正确？
- 状态是否可能部分更新或无法恢复？

## 安全

- 是否存在注入、XSS、CSRF、路径穿越、SSRF 或不安全反序列化？
- 认证、授权和租户隔离是否正确？
- 密钥、个人数据和敏感日志是否得到保护？

## 性能与资源

- 是否出现 N+1、无上界查询、重复网络请求或热路径 O(n²)？
- 缓存、批处理或并发是否引入一致性问题？
- 文件、连接、锁、线程等资源是否正确释放？

## 自动化测试

- 测试是否先证明旧行为会失败，再证明实现有效？
- 断言是否落在真实行为，而不是恒真条件？
- 是否覆盖关键失败路径和回归风险？
- mock 是否掩盖了真正的集成问题？

## 动态验证

- 核心用户路径是否实际运行？
- 错误、权限、空态和边界状态是否执行？
- UI 是否符合 ui-design，响应式和键盘行为是否正确？
- 数据迁移、外部集成或后台任务是否在合适环境验证？

## 典型严重发现

- 实现绕开或改变已验证的核心方案。
- 构建或关键测试失败。
- 存在可利用的安全漏洞或明确的数据损坏风险。
- 已确认问题没有防回归测试。
- UI 走查发现关键路径无法完成。
