# 测试用例模板

用例写清怎样验证和什么结果算满足要求；实际运行另记。位置遵循用户指定或公共工作约定，已有测试系统可以直接引用。

```markdown
# <范围>：测试用例

负责人：<负责维护本用例集的人或角色>
依据：<需求、规则、设计和接口的来源及版本>
范围：<覆盖与排除>

## <ID> <场景>

- 依据与风险：<来源、为什么验证；采用的方法或关键边界>
- 方式：<接口／集成／端到端／视觉交互／其他>
- 前置条件：<版本、环境、账号、数据和依赖>
- 操作：<输入与步骤>
- 预期：<可观察的输出、状态、数据及下游效果>
- 观察方式：<在哪里核对结果；无法观察的部分及原因>

## 覆盖与缺口

| 需求或风险 | 用例 | 缺口及原因 |
| --- | --- | --- |
| <来源> | <ID> | <无或说明> |
```

前置条件和输入要足以复现。重复运行会改变数据时，写明怎样恢复条件；需要外部副作用的步骤注明已有授权范围。预期缺少依据时交负责人确认，不能用当前表现填空。
