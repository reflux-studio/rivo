# 设计测试用例

开始时说明正在使用 `rivo-testing:designing-tests` 和本次范围。同一项工作中不重复声明。通过宿主发现的公共 `rivo` 技能取得入口与工作约定；公共包不可用时说明依赖缺失，不启动领域工作流。

测试预期来自需求和已确认规则，接口、设计和实现可帮助识别入口与观察方式，不能替代业务依据。用户只要求指定范围时，完成该范围即可。

## 流程

1. **核对依据和范围。** 读取用户提供或公共工作约定绑定的需求、规则、设计、接口与待测对象，记录来源和版本。已有团队材料和人类同事提供的材料同样适用；不要求产品或开发插件产物，也不要求全部源码。材料不可读或规则不清时记录影响，只阻塞依赖部分。
2. **按风险设计场景。** 从实际入口追到可观察结果和下游影响，覆盖适用的正常、异常、权限、兼容和恢复场景。有设计依据时加入视觉与交互预期。按需选择等价类、边界值、决策表、状态迁移和数据流，不为凑方法穷举组合。
3. **写用例。** 使用[用例模板](references/cases.md)，给出稳定 ID、依据、风险、前置条件、操作和可观察预期，以及适合的验证方式。核对最终状态、持久化和下游效果，不只检查成功提示或字段存在。记录覆盖关系和无法验证的部分。
4. **处理缺口。** 需求或设计冲突交对应负责人，方案缺口交开发处理；通过宿主发现的公共 `rivo:collaborating` 技能发起协作。提出建议，但不批准或修改他人的需求、设计或开发方案。预期确需变更时先核对负责人确认的依据，再更新受影响用例，不能为了匹配实现改预期。
5. **交付设计。** 说明覆盖、风险、待确认问题及执行所需条件。需要执行时转入 `rivo-testing:testing`；只做设计的请求在此结束。
