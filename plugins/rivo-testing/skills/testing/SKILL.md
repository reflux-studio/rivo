# 执行专业测试

开始时说明正在使用 `rivo-testing:testing`，并用一句话说明本次要做什么。同一项工作中不重复声明。

通过宿主发现公共 `rivo:using-rivo`，读取测试工作约定。公共包不可用时说明依赖缺失并停止领域执行。测试可以直接针对用户给定材料和运行中的系统进行，不要求完整源码或其他领域插件。

专业测试要发现问题、说明质量及风险。开发自测和代码审阅是输入，不能替代本次实际执行；同一会话切换角色也不因此成为独立质量保证。

## 流程

### 1. 核对提测条件

读取给定需求、规则、设计、用例和已有反馈，确认：
- 本次范围、风险及依据版本
- 实际运行或部署的版本；多组件分别记录，不能用本地提交代替部署版本
- 环境、账号权限、依赖、数据和已连接的相关工具
- 哪些预期可以观察，哪些需要补充来源或访问条件

用例不足时，加载 `rivo-testing:designing-tests` 补充本次需要的场景。条件不满足就记录受阻范围与解除条件，继续不依赖它的检查。

### 2. 准备数据和操作

核对创建、修改、清理数据及触发外部流程是否在已有授权内：
- 优先使用可辨识的隔离数据，记录初始状态
- 通知、支付、发布等副作用按实际授权执行，只暂停未获授权的部分
- 测试只维护本人用例、脚本、报告和获授权的隔离数据
- 脚本沿用已有测试约定，先确认目标环境和数据范围

产品代码、需求和其他角色的材料仍由对应负责人修改。

### 3. 执行用例并观察结果

先做最能影响质量判断的检查，再补充相关覆盖：
- 按风险选择接口、集成、端到端、视觉交互及适用的性能、安全或兼容检查
- 对照预期检查输出、最终状态，以及刷新或重查后的持久化
- 有下游承诺时检查真实下游结果；模拟或部分链路单独说明边界
- 界面对照可读取的设计版本，在相同窗口、数据和状态下检查视觉、交互与反馈
- 每项结果记录实际观察及证据，工具或环境不具备时记为受阻或未执行

E2E 只是执行方式之一。接口检查能直接发现的规则问题，不必全部挤到浏览器中；只能在完整用户流程中暴露的问题，也不能用接口返回成功代替。

涉及副作用的操作失败时，先核对实际状态再决定是否重试，避免一次未收到响应触发两次真实操作。

### 4. 探索并反馈问题

对尚不确定的风险安排有目标的探索：
- 写清这次要探索什么、允许的范围及时间
- 记录实际走过的路径、使用的数据和发现，即使没有预设用例也保留证据
- 发现差异时加载 `rivo-testing:reporting-defects`，核对依据、复现并交负责人处理
- 可以协助定位原因，但不代修产品实现或为了让测试通过改变预期

没有发现问题只说明本次探索没有发现，不能据此宣称未走过的路径已经通过。

### 5. 复测并回归

收到修复回复后，先确认实际运行的新版本：
- 重现原步骤，检查原问题的预期已经满足
- 根据修复影响选择相邻规则、角色、状态或下游流程做回归
- 记录每次版本、结果和证据，保留原始失败
- 无法确认新版本、条件不同或结果不可观察时，说明还不能关闭的原因

“这次没有再看到错误”只有在相同有效条件下完成预期检查，才构成复测证据。旧版本通过也不能证明新版本通过。

### 6. 给出质量结论

使用 [报告模板](references/report.md)，按公共 `rivo:writing-clearly` 交付：
- 分别记录通过、失败、受阻、未执行和不适用，不适用说明依据
- 说明已测范围、实际版本、缺陷、验证缺口及其影响
- 结论写为通过、未通过或存在验证缺口；关键失败或关键缺口不能写成整体通过
- 给出风险与后续建议，剩余风险是否接受、整项交付是否验收由有权负责人决定

在授权范围内清理数据并记录结果和残留。每次运行保留独立记录；更新汇总时引用真实运行，不改写旧证据。
