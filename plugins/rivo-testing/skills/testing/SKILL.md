# 执行专业测试

开始时说明正在使用 `rivo-testing:testing` 和本次范围。同一项工作中不重复声明。通过宿主发现的公共 `rivo` 技能取得入口与工作约定；公共包不可用时说明依赖缺失，不启动领域工作流。

测试可直接针对用户给定的需求和运行中的系统进行，不要求完整源码或其他领域插件。开发自测和审阅不能替代专业测试；同一会话或人员切换角色也不能因此称为独立质量保证。

## 流程

1. **核对提测条件。** 确认范围、需求和用例版本、实际运行或部署版本、环境、账号权限、依赖、数据与工具。多组件分别记录版本；不能用本地代码版本代替部署版本。预期不足时使用 `rivo-testing:designing-tests` 补充，不能根据当前表现编造。条件不满足时记录受阻范围和解除条件，继续不依赖它的工作。
2. **确认操作授权。** 核对创建与清理数据、外部流程、通知等副作用是否在已有授权内，优先使用可辨识的隔离数据。未经授权只暂停相关操作。测试只修改本人用例、报告、脚本和隔离测试数据，不修改产品代码、需求或其他角色产物。
3. **执行与观察。** 按风险选择接口、集成、端到端、视觉交互以及适用的性能、安全、兼容或其他非功能检查。E2E 是其中一种方式。按用例核对最终状态、刷新或重查后的持久化和承诺的下游效果；模拟或部分链路须标明边界。界面按给定设计、窗口、数据与状态验证视觉和交互。无法获得工具或环境的检查记为受阻或未执行，不虚构结果。
4. **探索和报告问题。** 围绕风险设定探索目标、范围与时间，记录路径和发现，即使问题没有预设用例也报告。发现差异使用 `rivo-testing:reporting-defects` 复现、保留证据并交对应负责人处理。测试可以协助定位，不代修产品实现。涉及副作用的失败先核对实际状态，再决定是否重试。
5. **复测与回归。** 收到修复回复后核对实际运行的新版本，重现原步骤并验证预期，再根据影响范围选择回归。未能重现失败本身不足以关闭缺陷；旧版本通过不证明新版本通过。保留原始失败和每次运行证据。
6. **给出质量结论。** 使用[报告模板](references/report.md)分别记录通过、失败、受阻、未执行和不适用及依据，说明实际观察、证据、缺陷、风险与建议。关键失败或关键验证缺口不能写整体通过；非关键缺口仍须明确。测试结论可为通过、未通过或存在验证缺口，剩余风险的接受和整项交付验收由有权负责人决定。

清理只在授权范围内进行，记录结果和残留；报告与证据按用户指定或公共工作约定保存，每次运行保留独立记录。
