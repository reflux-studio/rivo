# 共享工作区

需求默认放在 `.rivo/issues/<需求>/`，用户指定位置优先。只创建当前工作需要的材料。主文档直接放在需求根目录，按产物含义命名；参与方增加时不额外建立角色目录层。本页维护共用目录，product.md、development.md、testing.md 分别维护领域主文档和专有目录；这些参考是位置约定的唯一维护处，领域技能和模板不复制目录树。

`issue.md` 是每次接续或执行协作任务前的精简入口，只保留：

```markdown
# <需求标识>

| 参与方 | 角色 | 联系入口 | 负责产物/实际位置 | 必要授权边界 |
| --- | --- | --- | --- | --- |
| <ID> | <身份> | <用户给定的会话/联系人> | <文件或链接> | <范围> |

| 时间 | 发起方 | 接收方 | 协作记录 |
| --- | --- | --- | --- |
| <时间> | <ID> | <ID> | <详情链接> |
```

工单不记事项标题、问题、处理状态或回复日志。具体问题和往返放 `collaboration/<请求ID>.md`，格式及登记方式由 collaborating 维护。需要查看某项请求时再读详情，不每次通读历史。

工单登记实际来源及产物负责人，默认目录不覆盖这些绑定。只知道文件名或最近修改时间不足以确认有效版本。未登记归属、联系人重名或位置冲突时先核对，不能自行接管。

旧需求没有工单时从用户给定资料恢复，报告明确缺少的归属或联系信息，不自动搬迁、覆盖或为凑结构建全套文件。

## 共用材料

以下位置相对需求目录，所有角色按需使用：

| 位置 | 用途与命名 |
| --- | --- |
| research/<主题>.md | 调查材料与结论，按具体问题命名 |
| reviews/<被审对象>-<轮次>.md | 方案、用例或实施的审阅，如plan-01.md、test-cases-01.md、T01-implementation-01.md |
| assets/ | 当前设计与方案的附件，名称区分对象和用途 |
| evidence/<执行编号>/ | 每次实际执行的报告、日志与截图；执行编号区分验证主题、版本与轮次 |

共用目录中的每份材料仍有归属。新建材料时在文件中写明负责人、来源和依据版本；工单登记主要产物与实际位置，不逐条抄录所有附件。同名文件已存在时先读取并核对负责人，沿用同一主题的有效材料或按对象区分名称，不覆盖他人产物。专业测试与开发自测使用各自的执行记录；不能混写一份报告冒充独立验证。

当前方案原位修订，历史快照不成为另一份有效方案。待决问题归相应决定记录，调查和审阅引用问题编号；协作请求保存往返，执行进展归任务安排，不复制多份活动待办。用例与执行结果分开维护；缺陷正文只有一个维护位置，协作请求引用它，已有缺陷平台优先。

已核实的共享知识默认进入 `.rivo/knowledge/<主题>/`，整项需求在用户明确授权且各方结果核对后归档到 `.rivo/archived/<需求>/`。用户或团队既有知识位置优先；独立方法不强制创建项目知识库。其他角色负责的知识仍须交负责人修改。
