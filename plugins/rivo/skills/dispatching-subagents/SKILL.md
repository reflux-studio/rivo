# 委派子代理

开始时说明正在使用 `rivo:dispatching-subagents`，并用一句话说明本次要做什么。同一项工作中不重复声明。

主代理负责拆分、选择执行配置、协调依赖和核验结果。子代理完成边界清楚的任务，返回可检查的证据。子代理继承当前角色的权限，不因新会话获得其他产物的修改权。

## 流程

### 1. 判断是否值得委派

- **先看当前流程**：当前工作约定何时派发、是否需要独立审阅、产物写到哪里。保留这些要求，本方法只指导怎样委派
- **再看任务边界**：问题或交付结果能独立描述，所需输入能提供，验收能检查，才适合委派
- **比较收益与开销**：独立探索、隔离上下文、并行执行或独立审阅的收益，应超过传递材料、等待和整合的成本
- **短小任务直接做**：仅在当前流程没有要求派发或独立审阅时适用

没有子代理工具时，继续不依赖委派的已授权工作，报告哪些派发或审阅尚未完成。主代理自查不能算独立审阅。

### 2. 选择实际可用的执行配置

先核对用户偏好、项目的 AGENTS.md 或 CLAUDE.md，以及宿主实际提供的子代理工具和配置。用户或项目已指定的分工沿用；约定冲突、指定配置不可用时，说明影响，不自行绕过。

- **有选择空间时**：从实际可用且允许选择的配置中，按任务难度、错误代价、成本和延迟选择。明确、机械、验收清楚的任务优先低开销配置；复杂判断、高错误代价和关键审阅优先能可靠完成的配置
- **没有指定时**：有可选配置就按上述因素选择；宿主只有固定配置或不支持选择时，沿用当前配置
- **只使用真实能力**：工具支持且用户或项目允许时才设置模型或推理参数。不虚构模型名、参数或可用权限，也不切换主会话模型

### 3. 写清委派契约

有适用提示词时沿用，在其输入中补齐本次任务的信息。没有模板时，在派发消息中写清：

| 内容 | 要交代什么 |
| --- | --- |
| 目标与验收 | 要回答的问题或交付结果，怎样判断完成 |
| 输入与依据 | 原始要求、已确认决定、相关文件及版本、已有证据；假设与事实分开 |
| 范围与授权 | 工作目录、可读和可写范围、允许操作与禁止事项 |
| 依赖与协作 | 上游输入、共用契约、其他任务边界，何时交回主代理 |
| 返回与产物 | 结果、实际改动、验证命令与结果、未覆盖部分、受阻原因；当前工作给定的产物位置 |

独立审阅交给未参与被审工作的人或子代理。给它原始要求、决定依据、真实改动和验证材料，不只给执行者的摘要。

### 4. 隔离并行工作

- **按依赖并行**：只并行不需要对方未完成结果的任务。共用契约先确定，再派发依赖它的任务
- **划清写入范围**：每个可写文件或区域由一个执行者负责。重叠任务串行，或用宿主支持的独立工作区隔离后由主代理整合
- **共用环境也要隔离**：数据库、服务配置、端口和测试数据不能互相干扰。不能隔离就串行
- **保留已有改动**：交代起始版本和未提交文件，不覆盖他人的工作。共用文件的修改由委派者在本人权限内协调

负责人、依据和下一步记录在当前工作已有的安排中，不建立额外状态副本。临时子代理不是共享需求中的新角色；只有实际登记且授权可联系的参与方，才按 `rivo:collaborating` 处理跨角色请求。

### 5. 核验结果

- 对照委派契约，核实返回是否覆盖目标、范围和验收
- 查看实际文件、差异和证据，检查结论是否对应当前版本，不把“已完成”的报告当作事实
- 完成必要验证，区分静态检查、模拟验证与真实运行；整合并行结果后检查共用契约和相互影响
- 按当前工作要求交独立审阅、处理意见和保存产物，再报告完成。方法单独使用时，交付结果、证据和限制即结束

### 6. 按受阻原因处理

先判断缺少什么，再选择下一步：

| 原因 | 处理 |
| --- | --- |
| 信息不足 | 补齐要求、上下文、文件或证据；需要用户做决定时，只暂停依赖该答案的工作 |
| 环境受阻 | 说明工具、权限、服务或依赖的故障与解除条件；继续不受影响的任务，条件具备后再试 |
| 能力不足 | 材料与环境齐全，但仍无法可靠完成时，缩小任务或拆分；有可用且允许选择的更强配置时再升级 |

升级时说明改变了哪项配置，以及预期解决哪个能力缺口。固定配置下如实报告限制；重复同一配置的重试不是升级。
