# 整理已核实的知识

开始时说明正在使用 `rivo:knowledge-management`，并用一句话说明本次整理什么。同一项工作中不重复声明。

知识记录当前可依赖的认识，解释机制、约束和理由。未执行的目标、未经查证的猜测和旧版本结果，不能写成已经成立的现状。

## 流程

### 1. 确认本次范围

读取用户要求、本人角色和负责材料，核对已有确认与授权：
- **工作收尾**：根据完整上下文判断本人结果是否已经验收，不要求固定措辞。尚未确认的结果，先保留在原工作材料中
- **单独整理**：用户要求整理已核实的研究或资料时，在给定范围完成即可，不自行宣布整个需求结束
- **产物归属**：只维护本人获授权的知识。需要改变其他负责人内容时，通过 `rivo:collaborating` 处理

知识位置沿用用户或项目约定；共享需求使用公共 `rivo:using-rivo` 的工作区约定。没有位置约定时，说明建议位置并按本次请求落实，不为独立方法创建整套项目目录。

### 2. 对照实际核实结论

读取现有知识，以及本次决定、研究、工作结果和验证材料：
- **分清材料的含义**：调查描述的是当时查到的情况，方案描述目标，执行记录与证据说明实际做成了什么。知识写当前可依赖的结论
- **核对当前版本**：系统机制用最新代码或运行结果核实；研究发现核对来源时间、样本和适用条件。证据不足时标明限制
- **处理冲突**：实际结果偏离已确认决定时，交回原任务处理，不能通过改知识库替它补办确认
- **保留他人更新**：比较工作开始时读取的知识基线与当前版本。其他工作新增的内容保持原样，有冲突时先协调

### 3. 写入对应主题

按 [知识文档参考](references/knowledge.md) 选择适合读者的结构，加载 `rivo:writing-clearly`：
- 已有主题只改受影响的段落；独立的新主题才新建文件
- 首页补上新主题的导读和链接，让新读者知道先读什么
- 用连贯文字解释工作方式、边界和理由，精确定义集中成表，来源放在读者便于核对的位置
- 在原处写成当前说法，清理失效内容；仍适用于旧版本或其他范围的规则保留并注明条件

不重构与本次工作无关的知识。

### 4. 检查可读性与依据

对照原始来源检查事实、推断和未验证部分，确认引用能打开。让未参与本次工作的读者读完后复述关键机制或结论；能够委派且授权允许时，使用独立子代理做冷读检查。复述不出来的地方，回到正文补足解释。

无法做独立冷读时说明缺口，自查不当作独立检查。

### 5. 按授权归档并报告

只有用户明确授权整项归档、各参与方结果已核对，且没有影响知识正确性的未决问题时，才按共享工作区约定归档。一个角色完成不代表其他角色已验收。

归档包括需要保留的审计和运行证据；修复指向旧位置的链接，并核实目标存在。未获归档授权或仍有缺口时保留原目录，不迁移无关材料。

报告新增或改写的主题、实际检查、仍存在的限制，以及归档位置和链接处理结果；未归档时说明当前范围即可。
