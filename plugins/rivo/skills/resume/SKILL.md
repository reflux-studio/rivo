# 恢复工作并接续

开始时说明本次要恢复的目标。恢复要对照当前事实，旧摘要只能作为线索；已有位置、确认和授权继续沿用。

## 流程

### 1. 找到本次工作

用户给出位置时直接读取；没有位置时查当前项目的活动工作。只有唯一匹配才选用，多个候选交用户明确，不按最近修改时间猜。

旧材料没有工单或不符合当前目录时，沿已有来源核对，不自动迁移，也不为补齐格式创建文件。

### 2. 核对身份和材料

有工单时先读参与方和协作索引，确认当前角色、本人产物及相关待处理记录。随后按公共 `rivo:using-rivo` 中的领域约定，读取本次需要的材料。

用户只要求了解现状时保持只读。公共插件也不因此取得其他角色的修改权。

### 3. 对照实际进展

材料说的版本和实际结果逐项核对：
- **代码工作**：核对仓库、工作树、当前提交及未提交改动，区分已有实现和待做任务
- **研究工作**：核对原始来源、时间和适用条件，旧判断是否仍有依据
- **测试工作**：核对需求和用例依据、待测版本、环境以及实际执行证据
- **其他产物**：按其来源与依赖判断当前有效版本，不能只看文件名或摘要

旧版本通过的检查不能证明新版本通过。受阻、未执行和已经失败的部分分别保留，不凭完成标记补写验证结果。

### 4. 核对接续边界

确认当前负责人、工作位置、已有批准和授权。别人负责或无法确认已释放的工作，先通过 `rivo:collaborating` 协调；不清理、覆盖或暂存他人改动。

从历史记录恢复事实，不从历史进度推导新权限。

### 5. 说明下一步并继续

简短报告目标、有效依据、实际进展、缺口和下一步。用户要求继续且范围没有冲突时，加载适用的领域技能或方法推进，不停在一份恢复摘要上。

需要他人决定的部分提出协作请求，其余已授权工作继续。恢复摘要留在会话中；当前状态更新在本人已有产物，不另建交接副本。
