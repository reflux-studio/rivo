# 调研代码库

调研记录事实、稳定惯例和无法确认的问题，不借机提出无关改造。深度取决于用途：首次入场覆盖架构核心地图和工作入口；周期巡视对照已有认知只检查变化；专项勘测围绕指定模块或问题深入；交付前调查只收集足以支持当前决定的事实。已经能支持后续工作时停止。

## 1. 建立地图

- README、依赖和构建配置；
- 目录结构和主要入口；
- 模块、服务和职责；
- 数据流、存储和外部接口；
- 部署、环境和基础设施；
- 测试、CI 和监控；
- 历史复盘记录（默认在 `.rivo/archived/*/retro.md`）。

优先读取当前真实来源；已有总结只能作为线索，与事实冲突时以可验证来源为准并记录冲突。

## 2. 归纳惯例

- 命名和目录组织；
- 错误处理、日志和配置；
- 数据访问和状态管理；
- API、事件和任务模式；
- 测试层级和常用工具；
- 安全和权限边界。

一处实现只是写法，多处稳定使用才是惯例。新旧模式并存时明确适用范围。

## 3. 沿真实路径核验

选择两三条代表性路径：从入口进入，跟踪模块调用和数据变化，找到存储、外部依赖和输出，查看错误和测试如何覆盖，与架构描述交叉核对。

## 4. 验证工程命令

实际运行适用的：安装依赖、构建或类型检查、单元测试、集成或端到端测试、本地启动、代码质量检查。记录当前环境、结果和失败原因。亲自运行过的命令才能写成已验证。

## 5. 发布

输出模块和数据流地图、关键入口与外部接口、代码和架构惯例及出处、技术名词表（模块、服务和内部概念的项目内叫法）、构建运行测试和发布方式、环境依赖和监控、已知冲突与推断待确认项，以及来源索引。

按 `collaborating` 的产物发布约定发布；来源由外部团队维护时提出修改建议。
