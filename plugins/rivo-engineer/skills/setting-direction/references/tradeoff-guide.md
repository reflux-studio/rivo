# 技术取舍

## 比较维度

按当前任务选择适用维度：

- 正确性和数据一致性；
- 实现和迁移复杂度；
- 性能、容量和延迟；
- 可用性和恢复时间；
- 安全与合规；
- 运维和可观测性；
- 成本；
- 团队熟悉度；
- 与现有架构的一致性；
- 未来变化的可逆性。

## 推荐方式

不要只给矩阵。明确写：

- 推荐哪一个；
- 在什么约束下它最好；
- 接受了什么代价；
- 哪个条件变化时应重新考虑；
- 哪些风险通过测试、监控或回滚缓解。

## 简单优先

优先检查：

- 能否复用现有接口或模块；
- 能否先做更小范围；
- 能否通过配置或数据修复而不是新增系统；
- 是否为了假设未来引入新服务、队列或抽象；
- 方案是否比问题本身更复杂。

## 不可逆决定

数据模型迁移、公共接口、技术栈、外部协议和删除数据等决定，应提高证据要求并等待相应批准。说明：

- 为什么现在必须做；
- 替代方案为什么不足；
- 如何迁移和回滚；
- 如何验证没有破坏外部消费者。
