# 整体审阅提示词模板

全部批次完成后派一次。方括号是占位符，填完再发。

```
Subagent (general-purpose):
  description: "整体审阅：[需求名]"
  prompt: |
    全部任务都通过了预审和人类 CR。你要审的是它们**合起来**。

    每个任务单看都合格，合起来结构可能已经变形。这是你唯一要找的东西——
    单任务预审已经查过每个任务内部，你只看它们之间和它们合起来。

    ## 材料

    全量改动：git diff [交付起点 commit]..HEAD
    方向：[direction.md 全文]
    方案与任务清单：[system-design.md 全文]
    转向记录：[adr.md 全文]
    项目约定：读 .rivo/ENGINEERING.md

    ## 查这些

    1. **任务之间一致吗**——同一件事有没有两种写法。分散在多个任务里做的
       相似逻辑，命名、错误处理、数据访问方式是否一致。这是最常见的一类：
       每个任务的实施者都是 fresh context，它们不知道彼此怎么做的。

    2. **架构侵入累积到什么程度**——单个任务加一层间接、加一个依赖、放宽
       一处边界，都在可接受范围内。全部摆在一起看：
       - 模块边界比开工前更清楚还是更模糊？
       - 依赖方向有没有出现新的环？
       - 有没有形成一个"什么都往里放"的模块？

    3. **整体还在方向上吗**——分多次提交的改动合起来，是否仍然走在
       direction.md 说的那条路上。adr.md 里记的转向，代码里是不是真的
       转过来了，有没有留着旧方向的半截实现。

    4. **遗留物**——任务中途的临时代码、注释掉的旧实现；被跳过、被放宽
       断言、被删掉的测试；为兼容中间状态加的分支，现在已经不需要了；
       调试代码、硬编码的环境特例、密钥。

    5. **整体的过度工程**——单任务预审查的是单个任务内的过度设计，你查的是：
       - 为了让多个任务对接而引入的抽象层，现在还有必要吗？
       - 有没有一个抽象只有一个实现，而且以后也不会有第二个？
       - 整体规模和需求的分量匹配吗？

    6. **认知回写候选**——从本次全部 CR 意见和转向里，挑出对这个项目
       **一直成立**的偏好和约束。它们该进 .rivo/ENGINEERING.md，
       下次交付的实施者就带着它们开工。只对本次需求成立的不要挑。

    ## 输出

    - 必须改的条目，每条标明属于哪一类：**实现没对上方案** /
      **方案不成立** / **方向不成立**。编排者按这个分类决定回到哪一步。
    - 认知回写候选。
    - 结论一行：整体审阅通过，或者列出必须改的。

    你的通过不等于交付通过。后面还有人类的整体 CR。
```
