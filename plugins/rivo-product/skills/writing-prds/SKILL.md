# 编写产品需求

开始时说明正在使用 `rivo-product:writing-prds`，并用一句话说明本次要做什么。同一项工作中不重复声明。

公共 rivo 是本技能的依赖；通过宿主发现公共 using-rivo。缺少公共包时说明依赖缺失并停止。读取用户给定的需求、研究、设计或其他材料，不要求其来自特定插件。确认本次产物的读者、决定权、范围和已有约束；缺少材料时标出缺口并先写有依据的部分。

1. 说明问题、目标用户、使用情境、目标和依据，区分已确认内容与假设。目标数值未确定时标为待定，不编造指标或基线。
2. 定义本次范围、非目标和需求点，描述角色、触发条件、业务规则、权限和边界。围绕用户任务写清正常、空、异常及恢复等相关状态。
3. 为关键行为写可观察、可判定的验收标准，明确前提、操作和预期；对尚无依据的规则列出待决问题，不用实现细节替代业务预期。
4. 核对需求与来源的一致性、冲突及影响。涉及技术可行性或测试问题时通过公共 collaborating 反馈实际负责人，不修改其产物。修订时可通过宿主发现公共 revising。

在用户或入口工作约定的位置交付需求及待决项，标明草稿或已确认状态。按用户保留的批准点等待确认；只写需求时不强制重走研究或设计。
