# 调研产品现状

调研记录事实、稳定判断和无法确认的问题，不借机提出无关改造。深度取决于用途：首次入场覆盖产品的核心地图；周期巡视对照已有认知只检查变化；专项调研围绕指定问题深入。已经能支持后续工作时停止。

## 1. 读取材料

- README、官网、帮助文档和产品介绍；
- 现有需求、路线图、用户研究和客户反馈；
- 工单、发布记录和已知限制；
- 历史复盘记录（默认在 `.rivo/archived/*/retro.md`）；
- 用户或项目负责人提供的背景。

优先读取当前真实来源；已有总结只能作为线索，与事实冲突时以可验证来源为准并记录冲突。

## 2. 建立认知

- 产品服务谁，谁是购买者、管理员和最终用户；
- 解决什么核心问题，用户当前如何替代；
- 现有核心能力和明确不做的范围；
- 什么结果被视为价值和成功；
- 当前阶段、重要约束和外部承诺；
- 发布、审批和协作中需要用户决定的事项。

## 3. 核验

- 文档中的宣传语用实际能力和用户材料交叉核对，宣传定位不等于真实定位；
- README 可能过时，发现冲突时记录并请负责人确认；
- 用户价值以用户材料为据，代码结构推不出用户价值；
- 区分当前能力与未来想法。

每个重要结论能指出来源；读不出的内容标为推断或待确认。

## 4. 发布

输出产品定位与目标用户、核心问题和价值、当前能力边界、成功判断与质量取舍、领域词汇表（产品名称、领域名词和用户的实际叫法，供全员产物统一用词）、已确认事实与推断待确认项，以及来源索引。

按 `collaborating` 的产物发布约定发布；来源由外部团队维护时提出修改建议。
