# 实施

开始时说明正在使用 `rivo-development:implementing-plans`，并用一句话说明本次要做什么。同一项工作中不重复声明。通过宿主发现公共 `rivo:using-rivo`，读取开发工作约定；缺少公共包时说明依赖缺失，不自动安装或假装执行。

每次实施都是对方案的一次检验。接口能力、依赖行为或性能不符合预期时，带着证据和影响报告，必要时修订方案。

分工：

- **主代理**：维护实施安排，派发任务，核实审阅意见并处理方案变更
- **执行者**：实现任务，自测行为和方案假设
- **审阅者**：独立评估真实改动

## 进入条件

读取用户给定需求、设计、当前技术方案、相关决定和项目规约。继续共享需求时先读工单，核对参与方、本人产物、实际工作树和已有反馈，再对照实施安排、审阅报告及代码确认进度。

可以开始的条件：

- 方案已经确认；或处于修订中，但当前任务不依赖改动部分
- 用户授权了实施。批准方案本身不等于授权实施，已有实施授权继续沿用
- 推送、合并、发布等操作有相应授权；核对已有授权是否覆盖本次操作

开发读取用户给定的验收依据，不要求先安装测试插件或创建另一套测试用例。专业测试可以由人类同事或既有团队承担。

## 流程

### 1. 写实施安排

- 加载公共 `rivo:writing-clearly`，用于实施安排、当前结果和交付说明
- 按 [拆分方法](references/planning.md) 安排任务、依赖和归属，位置沿用当前工作约定
- 逐节对照技术方案和已给定验收依据，检查每个模块、契约和验证安排是否都有任务承接

覆盖完整且进入条件满足即开工，实施安排不单独送审。

### 2. 逐任务实施与审阅

加载公共 `rivo:dispatching-subagents`，安排执行配置、委派契约和并行隔离。按任务依赖推进，每项任务：

1. 按 [执行者提示词](references/implementer.md) 启动执行者。给出本任务条目、共同约定和材料的实际位置，由它自己读取方案和代码
2. 接收结果，按 [接收意见](references/receiving-review.md) 核实方案问题及实现选择，再按下文“实现与方案不一致时”处理
3. 按 [审阅者提示词](references/reviewer.md) 的逐任务模式安排独立审阅，给出通过或不通过、依据和验证范围
4. 属实的 P0 交执行者修复，重跑受影响验证，再交同一审阅者复核修复和影响面
5. 在实施安排对应任务处记录当前结果、未修问题和处理理由，引用实际审阅及运行报告

逐任务审阅从简：只看本任务的验收、契约、明显缺陷，以及本任务首次形成的重要结构。全面的工程质量和跨任务影响留给整体审阅。

执行受阻时，先区分原因：

- 缺少上下文，补齐材料后继续
- 材料和环境齐全但任务超出执行者能力，拆小任务，或在实际允许选择时换合适的配置
- 环境、权限或外部依赖未就绪，说明解除条件，继续不受影响的任务，条件具备后再试

缺少独立审阅能力时报告缺口，不把执行者自查算作独立审阅。反复使用同一失败配置不算解决受阻。

### 3. 检查重要结构再扩展

接续已有实现或候选补丁时，先对照方案和项目规约，核对职责落点、契约来源、共享抽象及扩展点与主流程的关系。现有代码只说明当前状态，不能据此认定重要选择已获确认。

关键机制首次形成时，检查代表性路径的职责、数据和依赖，再扩展到其他模块。发现未确认的重要选择或与规约冲突，带证据交有权负责人处理，只暂停依赖它的部分。

### 4. 整体独立审阅

所有任务完成并集成后：

1. 按审阅者提示词的整体模式安排未参与实现的审阅者，全量检查整体完成度、代码质量、实现效果、成本和影响面
2. 报告保存到当前约定位置，明确方案及代码版本，保留逐任务报告
3. 核实意见。属实 P0 由执行者修复，重跑受影响验证，再交同一审阅者增量复核

整体结论来自本轮集成结果，不能把各任务通过或旧版本报告相加当作当前通过。缺少能力或证据时如实报告。

### 5. 交提测

交出可检查的实现和简短说明：

- 实际改动及代码版本、工作树，需求和设计依据
- 开发自测、独立审阅的结果及覆盖范围
- 没修的 P1、P2、被拒绝意见及理由
- 已知限制、受阻检查、提测环境和数据等前提

开发完成不等于独立测试或用户验收通过。测试由用户、人类同事或已登记参与方接续，开发不自行启动其他领域工作流。用户明确要求在此验收时，提供对应结果；只有明确验收且收尾授权覆盖，才加载公共 `rivo:knowledge-management` 整理本人负责的知识。

## 实现与方案不一致时

先分清要改变什么：

| 需要改变什么 | 处理 |
| --- | --- |
| 范围、已有决定，或方案写明的行为、契约和验收 | 加载公共 `rivo:revising`，从受影响的依据开始核对，交有权负责人决定；只改本人负责的产物 |
| 职责边界、契约来源、共享抽象或控制主流程的扩展点等重要结构 | 即使方案没写，也在扩散前报告证据、影响和建议，交有权负责人处理 |
| 任务内的局部实现选择 | 执行者在授权范围选择并报告，主代理核实后记进实施安排 |

新事实需要查证时加载公共 `rivo:investigating`。业务预期有歧义时，通过公共 `rivo:collaborating` 交需求负责人；无人负责时交用户处理。修订期间，不依赖变化的任务继续。

## 修订任务与代码

上游的修订确认后，同步自己的任务和代码：

- 原位重写受影响的任务，当前结果说明必要实现选择及证据；不另建平行方案或状态摘要
- 删除失效的实现和注释；兼容、迁移或发布需要的旧路径与开关按方案保留，并说明用途
- 批量替换或改名后，先全文查残留再送审

读取缺陷反馈时，先核对反馈对应的版本。修复开发负责的产品代码和单元测试，重跑受影响自测，提供可复验版本交反馈方复测。专业测试负责的用例、脚本和报告由其负责人修改；混合目录按登记路径或测试集合确认归属。
