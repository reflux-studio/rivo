# 讨论技术做法

开始时说明正在使用 `rivo-development:converging`，并用一句话说明本次要做什么。同一项工作中不重复声明。通过宿主实际发现公共入口 `rivo:using-rivo` 并读取其领域约定；不能仅凭路径存在判断可用。缺少公共包或无法发现入口时，说明依赖缺失并停止领域执行，不自动安装。

读取用户给定的需求、设计和项目材料，以及适用的项目规约、已有技术决定和代码。材料可以来自文件、在线文档或同事；不可读时说明缺口，只暂停依赖它的部分。继续共享需求时先读工单，按公共约定核对参与方及产物归属。

用户决定方向和重要取舍，开发调查事实、提出建议并记录技术决定。开发只维护获授权的技术产物，不替需求负责人决定业务规则或修改其材料。业务歧义通过公共 `rivo:collaborating` 交已登记的产品负责人；无人负责、无法定位或联系时请用户处理。

## 流程

1. **核对范围与依赖**：沿用用户已有拆解，识别跨模块数据、接口、权限和发布条件。区分已确认范围、候选做法和待查事实。
2. **调查**：按宿主发现并加载公共 `rivo:investigating`，核对实际契约、职责、扩展点和存量适配。事实、推断和未知分别记录。
3. **讨论取舍**：先处理约束多个模块的问题。每个问题说明场景、依据、选项代价和建议；已有决定有冲突时指出来源，不默默覆盖。
4. **记录技术决定**：按 [决定记录模板](references/decisions.md) 记录范围、来源与待决事项；重要取舍按 [ADR 模板](references/adr.md) 记录。用户已决定但漏记的补记，不重新要求批准。表达按公共 `rivo:writing-clearly`。
5. **确认方案依据**：核对主场景、失败场景、初始数据和外部入口。影响主流程、跨系统契约或数据落点的问题未解决时，不当作设计完成。向用户复述关键做法并确认，已有确认沿用，然后进入 `rivo-development:writing-plans`。

批准后的决定需要改变时，加载公共 `rivo:revising`，核对决定权和影响；在授权范围更新技术产物，并通知受影响的负责人。
