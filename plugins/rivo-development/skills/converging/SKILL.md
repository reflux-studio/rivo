# 讨论需求与做法

开始时说明正在使用 `rivo-development:converging`，并用一句话说明本次要做什么。同一项工作中不重复声明。通过宿主发现公共 `rivo:using-rivo`，读取开发工作约定；缺少公共包时说明依赖缺失，不自动安装或假装执行。

用户给出的拆解和做法是讨论的起点。开发查事实、提问题、给建议，并记录技术决定及理由；范围、业务行为和重要取舍由用户或有权负责人决定。

本技能维护技术决定记录和 ADR。位置沿用用户给定材料、工单登记或公共领域约定；调查结论交公共 `rivo:investigating` 维护，技术方案交 `rivo-development:writing-plans` 编写。

## 流程

### 1. 核对范围

先读当前材料：

- 用户的请求、需求和设计。材料可以是本地文件、在线文档或同事提供的内容，不要求来自其他领域插件
- 项目规约和相关代码；读过知识库时，把版本或修改时间记进技术决定记录的依据
- 继续共享需求时，先读精简工单，核对参与方和自己负责的产物，再读已有决定、调查、方案及相关审阅报告

加载公共 `rivo:writing-clearly`，按 [决定记录模板](references/decisions.md) 维护技术决定记录，先写范围：

- **沿用用户的拆解**：已有模块划分时，核对遗漏、边界和依赖；没有时按可观察的结果拆
- **分清三类输入**：明确的范围、候选做法和待查事实分别记录。“同事之前接过一版”是调查线索，查过才算结论
- **核对最新要求**：旧需求、设计和代码与用户的新要求冲突时，查清影响。涉及其他负责人材料的，通过公共 `rivo:collaborating` 请求其确认和修改
- **模块写结果**：技术改造、数据迁移和上线准备也可以是模块，写清它服务于哪项结果

材料无法读取时说明缺口，只暂停依赖它的部分。开发不替需求负责人补定业务规则，也不改写对方材料；无人负责或无法联系时交用户处理。

### 2. 找出依赖并调查

先处理会约束多个模块的问题。各模块分头决定，容易对同一个字段或接口得出不同的定义。

- 找出跨模块共用的数据定义、接口、权限和发布条件
- 加载公共 `rivo:investigating` 查清现状，验证候选做法是否可行
- 核对契约来自哪里、模块职责怎样划分、扩展点怎样参与主流程，以及旧实现怎样适配。重要结构选择在扩散前讨论
- 调查改变了拆解或依赖时，更新技术决定记录的范围
- 现状复杂时画图，先核对“现在是什么样”，再讨论做法

### 3. 按轮讨论取舍

每轮开始前重读当前技术决定记录，上下文被压缩后也先重读。问题和建议与已有决定对照，有冲突时指出原决定及其来源。

每轮讨论前提已经确定、现在就能回答的问题。每个问题写明：

- **场景**：什么情况下要做这个选择
- **依据**：查到的事实，各选项的代价
- **建议**：推荐哪个，为什么

控制每轮范围：

- 当前能回答的问题一次问完，先问影响模块多的
- 依赖本轮其他答案的问题，留到下一轮
- 能查明的事实自己查，不拿来问用户
- 认为已有方向有问题时，带着证据和影响提出来

### 4. 记录本轮决定

一轮讨论有了答复，先记录，再准备下一轮：

- 每个技术决定记一行，注明谁在什么时候决定；处理完的待决事项保留原编号和结果引用
- 达到 [ADR 模板](references/adr.md) 门槛的决定另写 ADR，技术决定记录链接过去
- 没有实质选项的工作只保存调查结论，例如核对某项已有能力怎样接入。模块、依赖和 ADR 不要求一一对应
- 更新已有决定时，沿依赖检查下游决定是否仍成立；模块边界变了，同时更新范围
- 业务问题引用协作记录和负责人给出的有效依据，技术决定记录不成为第二份产品规则

### 5. 确认可以写方案

三条都满足才结束讨论：

1. **本期问题已处理**：待决事项已回答、被有权人划出本期，或同意延后并写明影响和解决时点。会改变主流程、跨系统契约或数据落点的问题不能当作已解决
2. **场景走得通**：拿主场景和失败场景沿模块走一遍，包括上线当天的初始数据和外部入口。缺事实就调查，缺决定就继续讨论
3. **理解一致**：简短复述完整做法和关键理由，交用户或有权负责人确认；已有确认沿用，不重复询问

确认后，说明接下来会写技术方案、组织独立审阅，再交确认，然后加载 `rivo-development:writing-plans`。

## 改变已有决定

方案批准前，在已有决定权和授权内随讨论改写。方案批准后需要改变范围或决定时，加载公共 `rivo:revising`，核对影响和决定权，再更新自己负责的技术决定及 ADR；其他负责人处理各自产物。

正文在原处写成当前的说法，修改过程留在约定记录中。获批后被替换的 ADR 按模板保留历史。用户做过决定、只是缺少记录时，补记后继续原来的工作。
