# 0.8.0 语言润色与流程核查

本次从 `v0.8.0`（`1ea1550`）开始，检查 README、九个技能、参考文档、提示词、插件简介、图中文字及 hook。目标是减少重复和过满的判断，让规则的条件、动作和理由更清楚。两轮编辑完成后，按用户要求将版本号升级为 0.8.1，随本次补丁提交。

这是一轮编辑与静态流程核查，由修改者自行复核，未做独立审阅或模型行为试用。

## 语言修改

README 用供应商审批的假设场景说明协作过程，减少开头、原则和阶段说明之间的重复。首次出现 ADR 时解释含义，并说明方案审阅、用户批准、实施授权和验收各自的作用。问题分级留在入口技能和审阅提示词中。

技能和插件简介去掉了河流比喻，改用实际动作描述交付。“第一轮就会暴露方向问题”“模型读错的地方和人一样”等判断改成适用范围与具体要求。图中文字及交付图源同步更新。

writing-clearly 不再要求原因只能写半句、段首先给结论或表格只能放短语。AI 腔清单用于检查句子的实际作用，保留必要的对比与不确定性，不按词语或句式机械删除。

## 已修正的规则问题

| 问题 | 影响 | 当前处理 |
| --- | --- | --- |
| 讨论中的小决定只要求写进尚未创建的 plan.md | 中断或切换上下文后可能漏记 | 暂记 note.md 的“已确认的方案细节”，注明来源，成文时纳入方案并标明去向 |
| 概述说每个分叉都写 ADR，参考文件却设有记录门槛 | 执行者可能过度建档，或误以为小决定无需保存 | 概述、出口检查和图中文字都按重要取舍与普通细节区分 |
| 逐任务审阅“只给通过或不通过”，后面又要求问题和证据 | 审阅可能只交一个结论，无法据此修复 | 保留轻审范围，要求结论、问题依据和实际验证范围 |
| 主技能说纯实现选择由主代理决定，执行者提示词说由执行者决定 | 委派权限不清 | 执行者在任务范围内选择并报告，主代理核实记录；行为规则和共同契约仍须交回处理 |
| 修订代码要求不留旧实现或开关 | 可能误删迁移、兼容和发布所需路径 | 删除失效内容，按方案保留仍有用途的路径与开关 |
| 知识技能的验收要求没有在入口处区分单独调用 | 单独查询或整理知识可能被要求先验收需求 | 明确验收条件适用于交付收尾，单独调用走原有对应分支 |
| 排障原则容易被理解为禁止实验性修改 | 可能无法通过实验检验假设 | 区分验证假设的实验与正式修复 |

相关规则已同步到主技能、参考文件及 README；没有调整阶段顺序、审阅次数、P0 通过标准或每轮提问范围。

## 仍需验证的流程选择

### 方案大幅修订后是否需要独立复核

当前规则只在首次定稿前做全量独立审阅，之后由用户确认。若修订改变核心契约、权限或迁移安排，原审阅不再覆盖新内容。本次去掉了“第一轮一定能发现方向错误”的理由，但保留审阅次数。可以试用按影响范围复核的办法，再决定是否增加触发条件。

> 位置：[writing-plans](../../skills/writing-plans/SKILL.md)，独立审阅。

### 一次问完全部可回答问题的负担

当前按工具上限分批发出，但仍要求同一轮问完前沿问题。工具容纳得下，不代表用户能轻松处理。应在真实需求中观察问题数量、答复遗漏和来回澄清次数，再判断是否允许按主题拆轮。本次没有恢复固定问题数量上限。

> 位置：[converging](../../skills/converging/SKILL.md)，按轮提问。

### ADR 门槛是否仍会产生过多记录

“有多个可行选项，且推翻会造成返工”可能覆盖大量普通技术选择。语言已区分重要取舍和普通细节，但判定标准本身没有改。应检查试用中实际生成的 ADR，判断是否需要补充影响行为、共享契约或跨模块约束等条件。

> 位置：[ADR 判定标准](../../skills/converging/references/adr.md)。

### 安装指引与宿主能力不足时的处理

README 现在说明插件清单与技能调用的区别，但仍没有经过验证的完整安装步骤。流程依赖子代理和独立审阅，宿主缺少相应工具时也没有统一的降级规则。应分别验证 Claude Code 和 Codex 的安装、技能发现与子代理调用；不能把读取了 SKILL.md 当作插件完整接入成功，也不能把自行检查称为独立审阅。

> 位置：[README](../../README.md)，接入与调用；[using-rivo](../../skills/using-rivo/SKILL.md)，宿主调用。

## 第二轮精修与复核

第二轮进一步调整了阅读顺序和指令表达。README 用“外部账号不能直接进入内部审批链”的假设场景展开选择、理由和后续问题，把授权识别细则和问题分级移出介绍段落。原有模板审批图说明的是另一组问题，正文已明确区分。

八个技能保留名称声明，但不再要求照念固定开场；模型应说明本次实际要做什么。删除了重复的“你在想／应当怎么做”表格，有用的授权、证据和范围提醒保留在对应步骤。独立加载时需要的输入、操作边界和报告要求仍在各技能与提示词内。

“交回当前工作”“按偏离分流”等表达改为具体责任人和动作，相关章节引用同步更新。知识收尾按完整上下文判断验收，沿用已有授权，不要求固定口令。推送、合并和发布仍要求相应授权，已有授权覆盖的操作不重复询问。

writing-clearly 的示例先列出已知事实，再用相同事实写成段落。原例中新增的通知时限和通知买家等细节已去掉，明确要求先查证缺失信息，不能靠补写让文章显得完整。

本轮逐篇通读九个技能，并对照参考文档检查授权、阶段转换、记录位置、问题分级和报告要求。保留了首次方案审阅、逐任务审阅、最终审阅以及验收后归档的顺序；每轮提问范围和 ADR 判定门槛未改。语法、链接与 hook 检查再次通过。复核仍由修改者完成，不属于独立审阅或模型行为试用。文风与文字一致性已完成本轮检查，前文列出的产品选择与宿主验证事项仍是后续工作。
